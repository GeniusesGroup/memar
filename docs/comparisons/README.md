# Comparisons
This directory holds **fair, public comparisons** between Memar and other projects that people often treat as substitutes for it.

It exists so a reader can see, without sales tone, **why Memar was started** and **where neighboring approaches stop being enough** — especially once a system grows past a single coding session or a single agent's workflow pack.

## What this folder is
- Comparative essays for humans (and agents) who ask: "Why not just use X?"
- A place that may record **negative or partial results**: X is good at Y; X does not replace Memar's job.
- Deliberately **outside** `docs/` facet companions. Settled *principles* that a comparison surfaces belong in the governing documents under `docs/` (with changelog provenance). This folder keeps the **comparative argument** readable end-to-end.

## What this folder is not
- Not a rejection list or a scoreboard.
- Not a claim that other projects are "bad." Many are strong at what they set out to do.
- Not a substitute for Memar's live documentation. After a comparison, work still runs through [`docs/`](../docs/) and [`.agents/skills/memar/SKILL.md`](../.agents/skills/memar/SKILL.md).

## Fairness rules
1. **State the other project's self-definition first** — judge it against its own purpose before measuring it against Memar.
2. **Separate layers** — session workflow, distribution mechanics, domain knowledge, and system-development framework are different jobs; conflating them produces false rivals.
3. **Credit strengths without borrowing their packaging** — useful ideas may graduate into Memar's model; harness rituals, marketplace shapes, and persuasion copy usually do not.
4. **Prefer durable claims** — write what remains true as models and tools change; avoid advice that only patches today's agent weaknesses.
5. **Keep load-bearing logic linear** — do not encode norms in grids or diagram blocks; use section titles and linear lists ([Written surface](../docs/documentation.md#written-surface), [Knowledge → Write for the structure of the subject](../docs/knowledge.md#write-for-the-structure-of-the-subject-not-for-todays-reader-limits)).

## Standing principles these comparisons assume
These are owned in Memar's documentation; comparisons apply them rather than re-deriving them:
- One continuous mental model as internal knowledge — not a menu of per-harness plugins that each ship a fragment ([Knowledge → A project carries one continuous mental model](../docs/knowledge.md#a-project-carries-one-continuous-mental-model)).
- Executable projections where generation belongs in code services — not endless prose recipes for each concrete artifact ([Knowledge → Knowledge and Code](../docs/knowledge.md#knowledge-and-code)).
- Memar is not distributed as host-tool plugins or marketplace cards; a consuming project installs a pointer ([Using Memar in another project](../README.md#using-memar-in-another-project)).
- Prompt / harness technique sits under Communication, not under Agency's foundation ([Agency → Prompt Engineering and Harness Engineering](../docs/agency.md#prompt-engineering-and-harness-engineering)).

Discover comparison files by listing this directory. Do not maintain a membership index here ([documentation.md → Content Rule](../docs/documentation.md#content-rule-no-fabricated-or-redundant-provenance)). One file per compared project, named after that project.
