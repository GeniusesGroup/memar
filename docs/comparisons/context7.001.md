# Comparison: Memar and Context7
**Compared project:** [upstash/context7](https://github.com/upstash/context7)
**Inspected at:** commit [`522c4db`](https://github.com/upstash/context7/commit/522c4db4fa2e1e31f1b320f09fa8c8fab376987a) ("chore(release): version packages (#3369)"), local checkout under `_refs/context7`. Read in the checkout: the MCP server, the CLI, the TypeScript SDK, the AI-SDK tools, the skills, the rules, the plugin and marketplace manifests, `SECURITY.md`, `server.json`, and the public documentation under `docs/`. Not available in the checkout and therefore not inspected: the hosted API backend, the parsing engine and the crawling engine, each named by the project as private (**Evidence**, `README.md:137`); no MCP server was started, no query was sent to the hosted API, and no account was created.
**Method:** four independent read-only passes over the checkout — one on its self-definition and every surface it ships to agent apps, one on the client code, one on the hosted service, its provenance and its freshness, and one on the shape of this folder's sibling essays — each claim carried with the file and line it was read at, and the load-bearing ones re-read by the drafter at those lines. Cross-checked against Memar's live `docs/`. Where Memar's own documents are silent on the compared subject, the silence was checked against the open questions the [Organization](https://github.com/GeniusesGroup/organization) project already carries; that project's content is named here and not quoted, and the conclusions drawn from it are marked as session analysis. Nothing was measured: no latency, retrieval quality, freshness, quota, token cost, or accuracy figure was reproduced, and every number below is a number Context7 publishes. Where a claim is inference rather than something its files state, it is labeled.
**Framing:** ruled by the owner (Omid Hekayati, 2026-10-11): a deep and fair critique, with the result applied where it is durable; and that where Memar is silent, the silence may be deliberate, so no silence is treated as a gap before the documents that would own it have been read. Positions marked as the owner's are his; positions marked as session analysis were reached in the session that commissioned this essay and are open to his ruling.

## 1. What each project is

### Context7 (self-definition)
Context7's front door is titled "Context7 Platform — Up-to-date Code Docs For Any Prompt" (**Evidence**, `README.md:5`), and it states its purpose in one sentence: "Context7 pulls up-to-date, version-specific documentation and code examples straight from the source — and places them directly into your prompt." (**Evidence**, `README.md:21`). It names the failure it exists to remove, three times, before it names itself: "Code examples are outdated and based on year-old training data", "Hallucinated APIs that don't even exist", "Generic answers for old package versions" (**Evidence**, `README.md:15-17`), and repeats the promise as "No tab-switching, no hallucinated APIs that don't exist, no outdated code generation" (**Evidence**, `README.md:37`).

It serves two consumers by two mechanisms (**Evidence**, `README.md:39-42`): "**CLI + Skills** — installs a skill that guides your agent to fetch docs using `ctx7` CLI commands (no MCP required)" and "**MCP** — registers a Context7 MCP server so your agent can call documentation tools natively". The MCP surface is two tools, `resolve-library-id` and `query-docs` (**Evidence**, `packages/mcp/src/index.ts:217`, `packages/mcp/src/index.ts:309`), and the server carries no prompts at all (**Evidence**, `packages/mcp/src/index.ts:199-208`).

It states its own limits where they cost it: "Context7 projects are community-contributed and while we strive to maintain high quality, we cannot guarantee the accuracy, completeness, or security of all library documentation", and it names a report button for the failure that sentence covers (**Evidence**, `README.md:135`); "This repository hosts the MCP server's source code. The supporting components — API backend, parsing engine, and crawling engine — are private and not part of this repository" (**Evidence**, `README.md:137`); and it discloses that "MCP-formulated queries are anonymously stored and used to benchmark retrieval accuracy and improve the documentation matching pipeline over time" (**Evidence**, `docs/security/data-privacy.mdx:44`).

### Memar (self-definition)
Memar is "a system development **framework** as **structure** document that gives you a structuralism mental model to understand the development model" (**Evidence**, `README.md:2`), and it refuses the role of an oracle: "Memar is not an authority that decides reality. Memar is a framework for constructing, examining, and refining mental models about systems." (**Evidence**, `README.md:4`) Its purpose is a chain from knowledge through thinking and intelligence to agency ([Framework → Memar's Purpose Space](../framework.md#memars-purpose-space-from-knowledge-to-agency) — **Evidence**), and its own governing statement about the compared subject is a boundary rather than a capability: "Knowledge work is the concrete case: the performed service over a live corpus — orientation, extraction, retrieval — is built in the Organization project and delivered under Enterprise, not specified here." (**Evidence**, `README.md:30`).

### Category distinction and layers
The cut applied here is by the job a reader would hire each project for, not by the layers a stack diagram shows. Four jobs touch each other, and they are not one job:

1. **Acquiring material the project does not own.** Context7's job. The question: *how does an agent obtain the current text of a third-party library's documentation?* The holder of the truth is the library's repository; the question is acquisition of a copy.
2. **Building and keeping one model's truth.** Memar's job. The question: *how does a project build the model of its own system and keep it true as the system changes?* The holder of the truth is the project; the question is truth maintenance.
3. **Delivering an interface to a consumer.** Both touch this. Memar holds that the party that knows delivers the client ([SDK → What an SDK is not](../modules/process/service-sdk.md#what-an-sdk-is-not) — **Evidence**); Context7 delivers the client of a *third party's* truth, by way of a second party.
4. **Shaping what an agent does and how it reasons.** Memar's core. Context7 touches it through its shipped skills and rules, which instruct an agent about where knowledge comes from.

The false rival appears when job 1 is read as an answer to job 2 — which is what happens the moment "the model hallucinates APIs" is met with a documentation corpus. A corpus can shorten the way from a question to a fact about a library; it does not touch whether a project's own model is true, whether its definitions are consistent, or whether an agent reasons from them. The two are adjacent in the vocabulary of agent work and separate in what they change.

The question that opened this examination — why move the learning of a library outside the session that will use it, through a secondary API, and why should documentation beside the code ever be a source of truth — names two real costs (a network round trip per question, and a second copy of a truth held elsewhere) and rests on one presumption that section 4 tests: that a library's interface and a model's memory are the same kind of thing, so that fetching the interface substitutes for knowing it.

## 2. Source status of the inspected checkout

**The checkout is a client and a manual for a hosted service.** The client half is complete and readable: the MCP server, a CLI, a TypeScript SDK, AI-SDK tools, skills, rules, and plugin manifests for ten agent apps, plus their tests. The service half is absent by declaration (**Evidence**, `README.md:137`): there is no backend code, no crawler, no parser, no schema, no migration, and no vector store in the checkout. Everything this essay says about how Context7 selects and ranks documents rests on the project's own description of the mechanism, not on the mechanism.

**The history is one commit.** The clone has a single commit, so the essays' single-commit condition applies ([Documentation — Comparison → Method requirements added by practice](../documentation-comparison.md#method-requirements-added-by-practice), item 2). What it costs here is specific and not general: no reader can ask why the refresh thresholds hold the values they hold, when a quality claim was written, what a trust score weighs, or what changed between the advertised versions named below. A project that cannot show why a number became a number is a different kind of source than one that can, and the claims this essay reports are exactly the kind that a history would settle.

**The documentation is the front door and it is checked as text.** `docs/` is a documentation site: prose plus a large image set (`docs/images/**`) whose screenshots show a dashboard, a billing page, a teamspace, and several SSO flows. No screenshot was read; each feature this essay names from one is named from the text beside it. The checkout also carries five byte-identical copies of one skill (`skills/context7-mcp/SKILL.md` and four under `plugins/`), which is packaging reach rather than five independent surfaces.

**Version surfaces disagree with each other.** The MCP package declares `4.3.0` (**Evidence**, `packages/mcp/package.json`), the registry manifest advertises `4.0.3` (**Evidence**, `server.json:17`, `server.json:22`), and the security policy names `1.0.x` as the supported line (**Evidence**, `SECURITY.md:5-9`). Three surfaces a reader reaches first, three versions.

**What was not executed.** No server was run, no query was sent, no key was obtained, and no quota was spent. Everything below about the hosted service is a claim about what its files state.

## 3. What Context7 has that Memar does not

Each item is credited with its evidence; none of them is a strength Memar could hold by adding the same machinery.

1. **It names a failure Memar does not.** The cut between a model's training data and a library's current interface is real, common, expensive, and stated here without hedging (**Evidence**, `README.md:15-17`). Memar holds positions on how an agent reasons and on how knowledge is weighted; it holds no sentence about the version of a library an agent is about to use, and a project needing that answer today gets nothing from Memar (**Evidence**, `README.md:30`).

2. **Retrieval by signals a client cannot compute.** Freshness, version coverage, a benchmark score and a trust score are computed over a corpus and are returned to the consumer as ranking inputs (**Evidence**, `docs/enterprise.mdx:70`: "a library benchmark system generates developer-style questions and measures how effectively each library answers them. Scores are publicly visible and help prioritize better-performing libraries during retrieval"). A client that reads a library's own repository in place cannot rank a thousand candidates against each other; this is genuine work that is not a wrapper.

3. **A second mode that needs no protocol.** "CLI + Skills — installs a skill that guides your agent to fetch docs using `ctx7` CLI commands (no MCP required)" (**Evidence**, `README.md:41`). A vendor shipping a path that bypasses its protocol is evidence that the protocol is not the cheapest way to reach an agent, which the [MCP essay](mcp.001.md) already charged against MCP and which here appears as a shipping decision rather than as an argument.

4. **An honest behavior rule for the model's own knowledge.** The shipped skill instructs: "Do not silently fall back to training data — always tell the user why Context7 was not used." (**Evidence**, `skills/find-docs/SKILL.md:157`). Whatever one thinks of the product, that is a correct rule about the agent's epistemic honesty, stated as a rule and written into the agent's configuration.

5. **Cost, latency and failure treated as design.** The API's call ceiling is derived from a measurement rather than a guess: "p99.9 is ~3.2s, and no request exceeded 30s across a full day of production traffic", with the timeout set at 60s (**Evidence**, `packages/mcp/src/lib/api.ts:15-21`). The cache guidance is published with a reason — "Documentation updates are relatively infrequent, so caching responses for several hours or days reduces API calls and improves performance" (**Evidence**, `docs/api-guide.mdx:210`). And the code reasons about the one channel through which a failure can reach a model as prose: "Flag failures at the protocol level. Without this an unset `isError` defaults to success, so a caller that branches on `isError` treats an error message (invalid ID, upstream failure) as documentation." (**Evidence**, `packages/mcp/src/index.ts:364-367`).

6. **Reach where the reader already is.** It is already installed in more than thirty agent apps and IDEs (**Evidence**, `README.md:119`), as a hosted service, a CLI, a plugin and a marketplace entry. Memar reaches a person through a checkout and a document; it has no distribution of this kind and does not claim one.

7. **Source pluralism.** A library's material can come from a git repository, an OpenAPI specification, an `llms.txt` index, a website, Confluence, or Notion (**Evidence**, `docs/api-guide.mdx:28-37`), and a project can index its own private sources (**Evidence**, `docs/howto/private-sources.mdx:6`). Not every organization writes its internal API down as markdown for a public site, and a corpus that reads OpenAPI and git histories reaches material a documentation-shaped tool cannot.

8. **Verification, thin as it is.** A library owner can claim a library, and application for verification is judged on quality and is free (**Evidence**, `docs/howto/verification.mdx:81-97`, `docs/howto/verification.mdx:110`). The mechanism is closer to self-service than to review, and it is still an attempt at the thing the corpus otherwise lacks.

## 4. Where Memar is stronger

1. **The answer arrives with its identity.** `query-docs` returns the upstream body verbatim — no header, no wrapper, no source line (**Evidence**, `packages/mcp/src/index.ts:357-363`) — while the call before it, `resolve-library-id`, does prepend one ("Available Libraries:", **Evidence**, `packages/mcp/src/index.ts:295`). So the model is shown a list of candidate libraries and then handed passages whose library, version, page, and revision it cannot name. Memar's position is the opposite by construction: what an SDK carries about a service, it carries in the service's own types, "and every type describes itself: the domain it belongs to, a one-line summary, a longer overview, and what an end user and a developer should do on meeting an occurrence of it... No type the SDK carries is therefore ambiguous, and the text a consumer reads about the service comes from those types rather than from a description written beside them" ([SDK → What an SDK is](../modules/process/service-sdk.md#what-an-sdk-is) — **Evidence**, `service-sdk.md:48`). A corpus passage is a description written beside the truth. That is the whole of the difference, and it is not small.

2. **The party that knows owns the deliverable.** Memar holds that the client is the service's own deliverable and that "no consumer re-derives the declared interface from a specification", with generation as derivation from the service's own declaration rather than authorship beside it ([SDK → What an SDK is](../modules/process/service-sdk.md#what-an-sdk-is) — **Evidence**, `service-sdk.md:12`, `service-sdk.md:46`). Context7 is that rule's failure case one layer out: a library's interface is delivered to consumers by a party that did not build the library, from a copy the library's maintainers never reviewed and owe nothing about. The copy is the interface, and it drifts — which the project's own refresh table admits (**Evidence**, `docs/library-updates.mdx:14-23`).

3. **Popularity is not a weight.** Memar's guidance to an AI system evaluating a claim is to "weight a source by its independent credibility and rigor — academic critique, formal specification, reproducible measurement — rather than by the source's popularity or by how many times a similar claim appears across the training corpus", and it says the reason in four words: "Popularity is evidence of adoption; it is not evidence of correctness." ([Terminology → AI-Assisted Usage](../terminology.md) — **Evidence**, `terminology.md:389`) Context7's retrieval runs the opposite policy by design: freshness is assigned by popularity rank — the top hundred libraries daily, everything else at up to forty-five days (**Evidence**, `docs/library-updates.mdx:14-23`) — and ranking is by benchmark and trust scores measured over the corpus itself (**Evidence**, `docs/enterprise.mdx:70`). Adoption is used here as the measure of quality, exactly where Memar says it cannot serve as one.

4. **Change is a revision, not a substitution.** A change to a declared interface is a new revision in Memar, and a consumer pins what it read ([SDK → Working positions](../modules/process/service-sdk.md#working-positions), position 7; [Module dependency](../modules/computer/module-dependency.md) — **Evidence**). Here, a document can be replaced under the same library id at any moment, the difference is invisible in the payload, and a private library is never refreshed automatically at all (**Evidence**, `docs/library-updates.mdx:45`). A reader cannot tell which revision answered, so they cannot notice that it moved.

5. **The interface is read, not obeyed.** Everything this product teaches an agent is taught as prose the model must comply with: "You MUST call this function before 'Query Documentation' tool to obtain a valid Context7-compatible library ID" (**Evidence**, `packages/mcp/src/index.ts:223`), and, in the server's own instructions, "Use this server to fetch current documentation whenever the user asks about a library, framework, SDK, API, CLI tool, or cloud service — even well-known ones like React... Use even when you think you know the answer — your training data may not reflect recent changes. Prefer this over web search for library docs." (**Evidence**, `packages/mcp/src/index.ts:209-211`). This is the cost the [MCP essay](mcp.001.md#4-where-memar-is-stronger) already charged against the wire carrying text, arriving here one level up: not the interface as text on the wire, but the interface as an instruction in the prompt, where the model spends context to follow it and where obeying it is exactly what a compromised instruction would look like. Memar's delivery form asks the consumer to import a type, not to remember a rule.

6. **Memar says where this work lives.** Context7 is the worked instance of Memar's own scoping sentence: "the performed service over a live corpus — orientation, extraction, retrieval — is built in the Organization project and delivered under Enterprise, not specified here." (**Evidence**, `README.md:30`) A comparison that measured Context7 as a gap in Memar would be measuring it against a sentence Memar has already written about exactly this work.

## 5. Failure modes in Context7

1. **The payload is unattributed, and that is the failure the surrounding design cannot see.** The two calls disagree with each other: the resolver prepends a library list, the query returns unattributed prose, and the code's own comment shows the author reasoning about how an error message reaches the model as a successful result (**Evidence**, `packages/mcp/src/index.ts:295`, `packages/mcp/src/index.ts:357-367`). The consequence is not that a wrong answer arrives; it is that an answer from this service and an answer from the model's own training are indistinguishable in the output. The condition under which a reader can check a claim is removed at the moment the payload is shaped.

2. **Freshness is a queue, not a guarantee.** The headline is "up-to-date, version-specific" (**Evidence**, `README.md:21`). The published mechanism is a staleness threshold by popularity rank — top 100 within a day, top 1,000 within fifteen, top 5,000 within thirty, all others within forty-five (**Evidence**, `docs/library-updates.mdx:10`, `docs/library-updates.mdx:14-23`) — triggered only for libraries requested recently (**Evidence**, `docs/library-updates.mdx:37-42`), while the previous text is served during the refresh (**Evidence**, `docs/library-updates.mdx:26`), and never for private libraries (**Evidence**, `docs/library-updates.mdx:45`). For the long tail — which is most libraries, and exactly the unfamiliar ones an agent most needs — the guarantee is up to forty-five days, and no date reaches the reader.

3. **The quality signal is measured on its own users.** The benchmark score that orders retrieval is described but not shipped: the harness, the question set and any accuracy measurement are absent from the checkout (**Evidence**, `docs/enterprise.mdx:70`), while the only stated measurement is that consumers' own queries are stored and used to improve the matching pipeline (**Evidence**, `docs/security/data-privacy.mdx:44`). A score that improves with use cannot tell a reader whether any particular answer got better. This is stated here as a limit of what the checkout can show, not as an allegation about the product's internal quality.

4. **The installer edits other tools' belief about where knowledge comes from.** `npx ctx7 setup` writes MCP client configuration, rule files and skill files into the configuration trees of ten agent apps (**Evidence**, `packages/cli/src/setup/agents.ts:123-390`, `packages/cli/src/setup/mcp-writer.ts:89-95`), with the API key written into those files in plaintext (**Evidence**, `packages/cli/src/setup/agents.ts:116-121`). The product's own front door warns that its corpus is community-contributed and cannot be guaranteed (**Evidence**, `README.md:135`). The security boundary the product asks a reader to accept is the boundary its convenience installer crosses: a corpus whose content is unreviewed by its publisher is installed as an instruction in the reader's agent.

5. **Every lookup leaves the machine, and the model waits.** Each tool call is one request to `context7.com` (**Evidence**, `packages/mcp/src/lib/api.ts:150`, `packages/mcp/src/lib/api.ts:190`) with a ceiling of 60 seconds (**Evidence**, `packages/mcp/src/lib/api.ts:21`), and the MCP server holds no documentation cache of its own. So the cure for "the model does not know" is: the model stops for a third party on every library question, keeps nothing afterwards, and has no fallback but its training data when the third party is absent or out of quota — the case the shipped skill covers by telling the agent to say so out loud (**Evidence**, `skills/find-docs/SKILL.md:152-157`).

6. **Capabilities described but not enacted are marked unevenly.** This is Memar's Content Rule applied to Context7's own surfaces as evidence rather than as an attack — the rule is that capability a project has not enacted must be marked wherever a reader can reach it, so no single surface claims more than the project holds. Four concrete cases, each read at the cited line: the SDK is marked "Work in Progress" in one README (**Evidence**, `packages/sdk/README.md:3`) and unmarked in the package list that advertises it (**Evidence**, `README.md:129`); automatic repository updates are described in the present tense as operating behavior (**Evidence**, `docs/enterprise/automatic-repository-updates.mdx:6-7`) with no tier mark where the enterprise tier is otherwise marked by navigation alone; the experimental server-card schema is marked in a code comment (**Evidence**, `packages/mcp/src/lib/constants.ts:37`) and nowhere a reader meets it; and the three version surfaces named in section 2 disagree without any of the three saying so.

7. **Its own score is invisible where it would matter.** Documentation carries a trust score, a benchmark score, a snippet count and a version list (**Evidence**, `docs/enterprise.mdx:70`), and none of it reaches the answer the model reads. The reader is told the corpus is ranked and never told by what this answer was ranked.

8. **One commit.** No claim in this essay about a Context7 number could be checked against a history that shows why the number is the number. That is stated once here, as the single-commit finding, and it is the reason the disclosure in section 10 is longer than a reader might expect.

## 6. Costs and limits on both sides

### Context7
- A hard dependency on a vendor for a question an agent must be able to answer offline; when the service is down, rate-limited, or out of quota, the fallback is training data, which is the failure the product exists to remove (**Evidence**, `skills/find-docs/SKILL.md:152-157`).
- Latency and money on every library question, and a hard ceiling on how many a session may ask — the tool descriptions carry a three-calls-per-question discipline (**Evidence**, `packages/mcp/src/index.ts:221-223`) that the client code nowhere enforces.
- Every query leaves the machine, with the enterprise telemetry on by default (**Evidence**, `packages/mcp/src/lib/telemetry-config.ts:1-3`) and the CLI reporting search keywords to the vendor on every command (**Evidence**, `packages/cli/src/utils/tracking.ts:3-9`).
- Lock-in by instruction: once the skill and rules are in the agent's configuration, the project's way of finding out about libraries is the vendor's.
- The copy is somebody else's liability. A library's maintainers change the truth; Context7 owes nothing to the project that reads the copy, and the project has no channel to the maintainer except a report button on a project page (**Evidence**, `README.md:135`).

### Memar
- Memar has no corpus, no retriever, no ranking, no index, and no documentation service. A project that needs the answer today gets nothing from Memar and must buy it or build it, which is the sentence Memar already writes about itself (**Evidence**, `README.md:30`).
- On the consuming side Memar is not silent but unremarked, and that is a different thing. A pass over Memar's own documents for this examination found the subject almost entirely absent: no document says what an agent is to do when it lacks a third-party library's shape; no document classifies a hosted third-party corpus as a source an agent may reason from; freshness — how a reader knows a text is current — is named only as a failure to be reported (**Evidence**, `docs/cognition.md:192`), never as something to be acquired; and no document says whether such a service would be a peer, an adapter, or part of the model. Nine other boundaries Memar draws about itself are scoping statements with an owner (session analysis, over `docs/framework.md:183`, `README.md:27`, `README.md:30-31`); these are not among them. The honest description is that Memar has scoped the service it would build and has not yet written the rule for its use.
- Memar's own answer, where it exists, is a document a session reads — and a session that reads a document has spent its context on it. A model that must read Memar's model to learn a library is in the position the MCP essay criticized from the other side.

### Both
- Neither removes the need to know which revision of a dependency the project is actually built against. A corpus ranks libraries and versions; the dependency graph of the project still has to be pinned, and a pin is the project's own declaration ([Module dependency](../modules/computer/module-dependency.md) — **Evidence**).

## 7. The adoption filter
The method writes toward absorbing what is durable into Memar's homes ([Documentation — Comparison → Fairness rules](../documentation-comparison.md#fairness-rules), rule 1). What is durable here is one obligation and one silence. No machinery, no surface, and no shape of Context7's travels.

### Absorb
- **An answer must carry the identity of what answered it.** Not Context7's way of doing it — a header prepended to one of two calls is a symptom of a design in which the payload is a copy — but the obligation it exposes: whatever a service delivers to a consumer, the consumer can say which declared thing it is looking at, at which revision. For a service that obligation is already met by the types an SDK carries ([SDK → What an SDK is](../modules/process/service-sdk.md#what-an-sdk-is) — **Evidence**, `service-sdk.md:48`); what it lacks is a statement for material that is not an interface — a document, a corpus, a retrieved passage — where the same obligation holds. Home: [SDK → Working positions](../modules/process/service-sdk.md#working-positions), as a position on what a delivery owes its consumer beyond call correctness. (Session analysis, for the owner's ruling.)
- **Popularity is adoption, not correctness — applied to retrieval.** Memar already says it ([Terminology → AI-Assisted Usage](../terminology.md) — **Evidence**, `terminology.md:389`), and section 4, item 3 supplies a worked counter-example from a shipped product: a corpus that orders freshness and quality by popularity rank is ranking by adoption. No new rule is needed. If the owner wants the instance in the governing document rather than only in this essay, the home is the same section, as evidence rather than as a rule.
- **A named instance of the boundary Memar already drew.** Section 4, item 6: Context7 is what "the performed service over a live corpus — orientation, extraction, retrieval" (**Evidence**, `README.md:30`) looks like when someone builds it. Whether the governing sentence gains a worked example is the owner's call; nothing else in the essay depends on it.

### Reject
- The corpus as a project's source of truth about a library's interface, and with it the presumption that fetching the interface substitutes for knowing it (section 4, items 1, 2, 4). Home: [SDK → What an SDK is not](../modules/process/service-sdk.md#what-an-sdk-is-not).
- Prose instructions to the model in place of a delivered interface (section 4, item 5). Home: [SDK → What an SDK is not](../modules/process/service-sdk.md#what-an-sdk-is-not), with the [MCP essay's guest-adapter ruling](mcp.001.md#guest-adaptation) unchanged.
- An installer that rewrites an agent's configuration and its belief about where knowledge comes from, as a side effect of being useful (section 5, item 4). No Memar document owns this rule; the essay records the refusal and leaves the owner a choice rather than inventing a home.
- The metering of quality by adoption (section 4, item 3) and the serving of freshness as a background queue while the previous text is answered from (section 5, item 2). Home: the same [Terminology](../terminology.md) section, as the negative form of a rule Memar holds.

### Guest adaptation
Nothing of Context7 is a guest adaptation, because it is not a protocol. Its MCP form is reachable by a Memar-built system only through the guest adapter [`modules/lib`](../../modules/lib/lib.md) already holds for MCP ([Lib Handoff → MCP as a guest adapter](../../modules/lib/lib.handoff.md#mcp-as-a-guest-adapter)), in the standing HTTP has toward sRPC — which places the whole product in the same standing: a protocol-shaped door onto a service the project consumes as a declared third-party dependency, with what crosses it named by the project's own declaration rather than assumed by the agent.

### Memar's own positions, routed to their homes
1. **What an agent is to do when it lacks a third-party library's shape.** This is the silence section 6 names, and the one item of this examination that is genuinely Memar's to answer. ## 8. Possible relationship
1. **Context7 is a dependency, never grounding.** A Memar-built system that wants library documentation reaches it the way it reaches any third-party service: declared as a dependency at a revision, through its own client, with what leaves the machine stated by the project. What its service returns is evidence the project may check; it is not what the project's own model is built from.
2. **Context7 is the standing instance of Memar's Enterprise boundary.** The comparison's most useful output for the model is not a rule but a demonstration that `README.md:30` describes a real and valuable product, built by someone else, before Memar built its own answer — which is an argument for the boundary being drawn where it is, and against its being read as a gap.
3. **The MCP essay's answer has a limit, and this is where it shows.** That essay concluded that the service, not the protocol, should deliver a typed interface to the consumer, and that the SDK belongs in the hands of the party that knows. Context7 shows what happens when the delivering party is not the knowing party: the interface arrives correctly and still cannot be pinned, attributed, or held to a revision. The conclusion survives; its scope is now drawn at the party, not at the protocol.
4. **The complementary local answer exists and is older.** The MCP essay's own record of the practice — a team replacing an MCP server with a script the agent could read and run — is the same shape as the strongest argument for this product: a procedure on the machine the model reads as text, not a description it must parse from a network. Context7 ships that shape as its CLI mode (**Evidence**, `README.md:41`) and still routes the substance across the network; the fully local form is a dependency read in place, which no service in this comparison supplies.

## 9. Decision
Context7 is not a substitute for Memar and is not in its category. Its job is acquisition of material the project does not own, from a corpus held by a party with no duty to the project; Memar's job is the truth of a system the project does own. Measured against Memar on its own subject, Context7 is not a rival but a boundary marker: it is the performed service over a live corpus that Memar names in `README.md:30` and does not specify here.

Memar takes one obligation from this examination — that a delivery owes its consumer the identity of what answered — and one silence from it, which is reported as a question with an owner rather than filled. No machinery of Context7 enters Memar: not its retrieval, not its scoring, not its rules, not its skills, not its installer, not its marketplace.

The result is also a correction to the framing the examination began from, and it cuts both ways. The claim that a documentation service is a secondary intermediary whose answer must never be authoritative is right in the case this essay examined, and for a reason sharper than "documentation is a copy": the answer Context7 returns carries no identity, is ordered by adoption, is refreshed by a queue, and is told to the model as an instruction rather than delivered as a type — so the reader cannot check it, cannot pin it, and cannot notice when it moves. A service that delivered each answer with the library, version and revision it came from, and let the project hold the pin, would not be the problem this essay describes. Whether Memar states that generally, and what a Memar-built project should do when it lacks the answer, is for the owner.
