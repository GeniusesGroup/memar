## Open Questions

### One identity or several representations of it?
- State: two identity schemes already exist in this document and neither is declared canonical over the other. The human-readable form is a URN — `urn:giti:{domain-name}:{structure-type}:{structure-name}` — and the compact form is the first 64 bits of the SHA3-256 hash of the media type, transferred base64 when the protocol is string-based, with zero reserved for "no data structure". Neither section says how the two relate: whether the URN is the canonical form of which the hash is a projection, or whether they are independent identifiers that happen to be derivable from each other. Around them, at least three names are already in use for shapes of the same question: [sRPC → Service ID](../net/sRPC.md#service-id) states that a Service ID is the same as the `MediaTypeID` of the service's media type, and the [Error protocol](../process/error.md#identity-and-equality) carries `DataTypeID` as a type's identity, so the compact form already has two names and no owner.
- The owner's position, recovered 2026-09-30 from an audit of Omid Hekayati's Go-community Telegram-group messages (gopherconf.ir, Gommunity), is that identity is not one interchangeable string: a human-readable form exists because a non-technical administrator must be shown something when access is being granted, and a path segment is not an acceptable way to name a service in that conversation; a compact form exists for the registry and the wire; and a local form exists for dispatch. Three positions from the same discussions are already settled elsewhere and are noted here only so they are not re-proposed as if they were open: an identifier is not text — a UUID-sized value is a fixed-size value, and a string is for human-language content; a locator is not an identity ([GP](../net/giti.md) and [Content → Reference as a Relation, Not a Property](../../content.md#reference-as-a-relation-not-a-property) draw that line); and the Type document's human-facing identity belongs to the Type as localized metadata in companion artifacts rather than in a wire identifier ([Type → Type Metadata](../../type.md#type-metadata)).
- Question for the owner: is the URN the canonical form with the hash as its wire projection, or are they independent identifiers with a stated derivation — and what is the canonical name for the compact form, given that `DataTypeID` and `MediaTypeID` already both denote it?
- Next: decide together with [SDK Handoff → What the declaration artifact is](../modules/sdk.handoff.md#what-the-declaration-artifact-is) and [GUI Handoff → Page state and history have no protocol text yet](../gui/gui.handoff.md#page-state-and-history-have-no-protocol-text-yet): all three derive their identifiers from this document's scheme, so a change here propagates into `../modules/sdk.md`, `../gui/gui.md`, and `../net/sRPC.md`. Note also that this document's Goals section carries an empty entry, so what the protocol is for is not yet stated in its own words — worth settling in the same pass, since the identity question cannot be answered without it.
