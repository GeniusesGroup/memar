## Open Questions

### Do the abstract data types belong under `computer`, or under `math`?
- State: the element index is not declared among the numbers (ruled 2026-09-27, owner) — it is declared with the containers, at [`modules/computer/adt/container/protocol/index.kh`](../../../modules/computer/adt/container/protocol/index.kh) as `Container_ElementIndex`, and the math folder's [README](../../../modules/math/README.md) states the boundary. What raises this question is that ruling: an index is not the only declaration that sat on the wrong side of it. The containers, arrays, lists, graphs, hash tables, queues, stacks and markers are all declared under `modules/computer/adt/`, and no document says a data type belongs to a computer rather than to a number. `modules/math/integer/protocol/adt-container-index.kh` remains on disk holding nothing but its license header and a pointer to the container's declaration; removing it is the owner's call, not this entry's. (Raised by the memar-go port.)
- The question, for the owner: do the abstract data types belong under `computer`, as they stand, or under `math`? What each answer means. (a) Under `computer`: the math folder's membership criterion stands as it is written, and the boundary is stated on the side of the folder that owns the containers only once `modules/computer/adt/` carries a README of its own. (b) Under `math`: the math folder's criterion widens from numeric magnitude to containers, and every `Container_*`, `Array_*` and `HashTable_*` name the port gave those declarations is then a name answering to the wrong module — the port qualified them by their module under the [qualified names rule](../../../modules/khayyam/rules/qualified-names/qualified-names.md), and no rule re-qualifies a name for a module that has moved.
- What waits on the answer: nothing in the toolchain — the M1 frontend resolves an `in` through the file system by path and knows no module boundary, so no declaration is refused either way. What waits is the naming: the qualified names are settled in the corpus as they are, so the answer decides whether they are right or merely tolerable, and moving a module is a corpus-wide rename rather than a move of files. Nothing here blocks the question about a common numeric abstraction ([Math Handoff → Is there a common abstraction over all numeric kinds?](../math/math.handoff.md#is-there-a-common-abstraction-over-all-numeric-kinds)), and that question does not block this one.
- Path: owner ruling, then either a README for `modules/computer/adt/` stating its membership criterion, or a widened criterion in [Math → Realization membership](../math/math.md#realization-membership); the element index's home follows whichever side owns containers and is not decided separately.
