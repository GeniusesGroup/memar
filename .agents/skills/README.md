# Skills
This folder holds agent practices. The name `skills/` and the `SKILL.md` filename are kept for interoperability with the current AI ecosystem rather than as Memar's own terms: a **skill** is a capability an agent possesses, acquired through learning or experience, and a document cannot literally be one. What these files contain are **practices** — explicit descriptions of how a kind of reasoning or task is to be performed — from which the corresponding skill may gradually emerge:
```
Content → Practice → Skill
```

The word *practice* is closer to the intended meaning than *skill*, but it is not perfect: a practice describes an established way of approaching a task without implying its reader already has the ability, where a manual teaches and an experienced practitioner performs. These words overlap in everyday use and differ across communities and industries, so where the label is ambiguous the definition decides ([Terminology → The Default Meaning of an Unreferenced Term](../../docs/terminology.md#the-default-meaning-of-an-unreferenced-term)).

Memar exposes a single practice in this folder, [`memar/`](./memar/). Splitting it into peer skill packs has been tried and rejected: a project's knowledge is one continuous mental model, and a Skill file is a projection of access into a host tool rather than a partition of that model ([Knowledge → A Project Carries One Continuous Mental Model](../../modules/knowledge/knowledge.md#a-project-carries-one-continuous-mental-model)). What a Skill file may contain — its front matter, progressive disclosure, bundled resources, writing style — is specified in [Documentation → Practice](../../modules-plugable/knowledge/documentation/practice/practice.md) and is not restated here; the format that specification was adopted from is documented at [agentskills.io](https://agentskills.io/specification).

The scripts that install this configuration into a project or into an agent app are [install.sh](../scripts/install.sh) and [install.ps1](../scripts/install.ps1); read each file's opening comment and `--help` before running it.

## Known Problems of the Current Skill
Recorded so they are not forgotten; the current route stays until a better one is found.

- **Solved: the skill repeated documentation.** `memar/SKILL.md` named, section by section, the passages an agent must read before an act. Which passages each kind of act requires is now declared once, in the lists of the content module's rule [Normative References](../../modules/knowledge/content/rules/normative_references/normative_references.md), one per [task kind](../../modules/management/task/labels/task_kind.py), and `memar ai get-task-init-context` and `memar content get-act-context` print them; the skill only says to open a session with its act's kind and to read every part those commands print. The skill still names the documents its own runtime rules cite, and a subject's documents are still found by searching, since subjects are not kinds.
- **Partly solved: telling the agent to read does not work.** Pointing at everything, and then naming the sections, both left agents skipping the documents and designing from what they had learned, which is usually wrong for Memar. The reading now arrives as command output, in ordered parts under a runtime's output cut, so an agent that runs the command has it in context. Whether every part is run, and whether the context command is run again when the act changes midway, still rests on the agent following the skill.
- **The word skill is a poor name** for this concept (see above).
- **Direction under study:** the Practice documents (for example [Modeling Practice](../../docs/modeling.practice.md)) already follow the Skill front matter. Their `description` fields could be improved; the context commands already print a Practice's `description` above its first passage.
