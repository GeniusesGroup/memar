# Host
The two files here wrap a tool the host already has: a filesystem (`fs.py`) and version control (`git.py`). Each carries a constraint a session improvises past when it is left to free-form shell habits — recoverable deletion, history-preserving moves, a guarded restore, no `git rm` — and none of it carries a capability the host tool lacks.

**This folder is deliberately not under `memar`, and the path is what says so.** Memar reaches itself through one command, and what that command routes to is what Memar itself does: installing it, opening a session's scratch folder, and reading, relating, auditing, and writing the written content of a checkout. A session that never touches this folder and never installs anything here is doing Memar work perfectly well. What lives here acts on the *host's* tools instead, and a command that carried it would read as Memar offering that tool — which is a claim Memar does not make and, where its critique of version control is concerned, must not appear to make.

The distinction is the one the label [`guest`](../../../modules/knowledge/classification/primitive/guest.md) draws for foreign protocols: the manifest carries the claim that the thing is here and is not Memar's own, and nothing Memar owns is mirrored under a guest's name. What that label means is a protocol surface Memar does not own, so its membership criterion is narrower than these two files meet — a filesystem listing and a git rename are generic mechanisms, not contracts an outside authority defines. The claim travels; the name does not, because the name already holds a narrower meaning.

So a caller reaches these files by path, from the checkout `MEMAR_ROOT` names, and neither of them is a `memar` verb. The rules a session follows with them are in [Scripts → Deleting, moving, restoring, and committing](../README.md#deleting-moving-restoring-and-committing); the why of each constraint is in each file's own docstring, and usage is in its `--help`. Usage is the interface; do not add a recipe catalog here.

`git.py` is the entry and `--help`; each of its verbs is a file of its own, `git_commit.py`, `git_rename.py` and so on, and the lock waiting (`git_lock.py`), the private index (`git_index.py`), the staged-change checks (`git_staged.py`) and the way git is run in a named repository (`git_run.py`) are the files they share, and `git_sessions.py` is how `commit` names the sessions a commit carries out. A caller runs `git.py`, never one of those.

That last file is the one place this shelf meets Memar's own: a commit is refused unless the sessions it cites are ones `memar session show` finds. It asks that command as a process and imports nothing from `services/`, so where a session's folder is and which branch keeps its records stay facts of the services that own them, and the shelf still carries no Memar capability of its own.
