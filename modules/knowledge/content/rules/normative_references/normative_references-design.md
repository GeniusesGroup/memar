# Normative References — Design
A design decides what something is before anything is built from it, so it reads how Memar discovers a model, where a model ends in a module's contract, and what a protocol is.

- [Modeling → Abstract](../../../modeling/modeling.md#abstract) — the model is the primary artifact, discovered as a graph before any implementation commitment, and an abstraction is justified by an autonomous responsibility. `reviewed 281779cf590d`
- [Modeling Rule → Model Reading](../../../modeling/rules/model-reading/model-reading.md) — a model's nodes, edges and paths are read as they stand before it is extended or criticized. `reviewed 24a9b359805c`
- [Modeling Rule → Requirement Context](../../../modeling/rules/requirement-context/requirement-context.md) — a model built for the wrong problem is not repaired by a better decomposition, so the reasoning above the requirement is examined first. `reviewed 408975e950b5`
- [Modeling Rule → Initial Discovery](../../../modeling/rules/initial-discovery/initial-discovery.md) — the questions asked before any node is proposed, where no model exists yet. `reviewed 57a7e845f0e8`
- [Modeling Rule → Modeling Workflow](../../../modeling/rules/modeling-workflow/modeling-workflow.md) — a design ends in a module's contract, and its fifth step is the gate. `reviewed c8900bbbb4cb`
- [Modularity Rule — Kernel Neutrality → The rule](../../../modularity/rules/kernel-neutrality/kernel-neutrality.md#the-rule) — what a kernel module may fix, the test that tells its subject from an organization's choice, and the order placement is asked in. `reviewed cdbf1580d84d`
- [Modularity Rule — A Concept Has One Owner Module → The rule](../../../modularity/rules/one-owner/one-owner.md#the-rule) — each concept is declared once in its subject module; others import it; a missing owner abstraction is a gap task, not a copy. `reviewed 8f65158d502f`
- [Documentation Rule — A Document Restates No Code → The rule](../../../../../modules-plugable/knowledge/documentation/rules/document-restates-no-code/document-restates-no-code.md#the-rule) — a design writes its types, fields and edges as Khayyam in the module's protocol and edge folders, and its document holds only the concept, the reason and the rules. `reviewed 45c0f93b4b20`
- [Documentation Rule — A Document Names Only Its Own Domain → The rule](../../../../../modules-plugable/knowledge/documentation/rules/document-names-only-its-own-domain/document-names-only-its-own-domain.md#the-rule) — a design's document names no concept of a domain its module does not import, and links a rule rather than restating it. `reviewed d40ab8e45c6d`
- [UI Rule — A Widget Aggregates, a Service Does One Thing → The rule](../../../../computer/ui/rules/widget-aggregates/widget-aggregates.md#the-rule) — aggregation of services and domains is only a widget's work; a base service never joins another domain's answers. `reviewed b00c0f73702b`
- [Service Rule — A Service's Home Is the Domain of What It Acts On → The rule](../../../../process/service/rules/home-follows-what-it-acts-on/home-follows-what-it-acts-on.md#the-rule) — a service is placed in the domain of what it acts on, not of the library it calls, and imports the owner of each concept it uses. `reviewed 52ec3efafa3b`
- [Modularity Rule — A Refactor Moves in Order → The rule](../../../modularity/rules/refactor/refactor.md#the-rule) — a design that moves or rewrites something existing states the order it will be done in. `reviewed b235f30aee30`
- [Task Rule — Later Work on a Task's Result Returns to That Task → The rule](../../../../../modules-plugable/management/task/rules/later-work-returns-to-its-task/later-work-returns-to-its-task.md#the-rule) — a design that follows a finished task's result or a ruling on it continues that task and opens no new one. `reviewed a15faba581e0`
- [Protocol → Abstract](../../../protocol/protocol.md#abstract) — what a protocol is, since a design that decides a contract decides one. `reviewed 2ab51295db0f`
- [Protocol Rule — A Protocol Is Written in a `protocol/` Folder → The rule](../../../protocol/rules/protocol-folder/protocol-folder.md#the-rule) — every abstraction lives in a `protocol/` of its owner; the module main folder stays small. `reviewed 035d3496fe1e`
- [Protocol Rule — A Protocol Is Written in a `protocol/` Folder → Placement test (refuse the main folder)](../../../protocol/rules/protocol-folder/protocol-folder.md#placement-test-refuse-the-main-folder) — Service/widget types, Request/Response, and single-service ports never go in the module main `protocol/`. `reviewed 5eb168189507`
