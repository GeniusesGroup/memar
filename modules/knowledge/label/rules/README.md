# Label Rules (`modules/knowledge/label/rules/`)
Rules for the conditions this repository holds a label to: what making one is, and what a reader may conclude from where it stands. The concept they check is [Label](../label.md); a Rule here states what an owner requires when checking work against it, and does not restate it. The general concept of Rule is [`modules/process/rule/rule.md`](../../../process/rule/rule.md).

| Rule | Subject | Tier | What it is |
| --- | --- | --- | --- |
| [A Folder Is a Label](./folder-label/folder-label.md) | A folder, a path, and the kinds of label a path holds | Governance | Making a folder is labelling; a path says one kind per position and is not subordination; kinds combine rather than nest |
| [Category Depth](./category-depth/category-depth.md) | The levels between a placement and a module | Governance | A category is one level, and a facet is part of its module, not a sibling |

The placement rules, which check the labels `kernel`, `pluggable` and `bundle`, are [Modularity's](../../modularity/rules/README.md). No check runs these today.
