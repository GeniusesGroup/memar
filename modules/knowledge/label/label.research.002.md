## 1. Problem statement
The owner's ruling (this request), in four parts:

1. `.agents/memar/labels.md` is one central file that holds the definition of every free label (`- word(identifier): Topic(identifier)`). It will break soon: every domain and every project writes into it, it is merged by hand across clones, and it makes one place the owner of all vocabularies. **Each domain must declare its own labels and its own statuses.**
2. Even a Markdown file is the wrong form. A label and a status are **code**, not explanatory text. The repository already says so: [A Fact in Code Is Written Once](../documentation/documentation.md#a-fact-in-code-is-written-once) — a closed set a program reads, written as prose, is a copy no check keeps true.
3. Prose may still exist, in the shape of [contract/edges/status/status.md](../../rights/contract/edges/status/status.md): one category document that explains the whole set, with what is not yet certain written in the handoff. When a label or status becomes certain, it is **code**, even if the code only returns the values.
4. That code must **return the values for registration by whichever storage or memory tool is used, without choosing the store**. Registering in MySQL (or a graph, or a file) is not the declaring code's job. The owner's model is the **definition of an Error**: a domain declares its errors as typed values; a different layer decides where they are kept.

What this document must settle, so development can go on without the owner present: the shape of the declaration (what a domain writes), the shape of the registration seam (what a storage/memory layer reads), what happens to the free labels (`Topic`) that today need no declaration, and what is done with the existing `labels.md` and the existing prose status documents.

## 2. What exists today
Evidence gathered from the repository; each item names the file so it can be re-read.

**The registry file and the code that reads it.**
- [`modules/knowledge/label/services/plan_labels.py`](../../process/session/services/plan_labels.py) fixes `REGISTRY_FILE = .agents/memar/labels.md`, parses it with `LabelRegistry.parse` and caches it by mtime. `memar label add` appends a line when a free word is first used. - So the model is already half right: **closed kinds are code** (`TaskKind` in [task_kind.py](../documentation/plan/labels/task_kind.py), whose docstring argues exactly the owner's point), while the **free kind `Topic`** ([topic.py](../documentation/plan/labels/topic.py)) is deliberately *not* listed in code — "a kept list in code would stop a new subject at the moment it appears" — and therefore needs the one central file. **The label domain.** [label.md](label.md) says a label has an identifier, "a label is defined once, in one place", its definition takes labels, and "registries of what a particular word means live outside this module": [law-labels](../../../modules-plugable/rights/law/labels/labels.md), [thing-labels](../../../modules-plugable/knowledge/thing-labels/thing-labels.md), [account-labels](../../../modules-plugable/economics/account/labels/labels.md), plus the task-labels loop under `modules/management/task/edges-loop/task-labels/`. **Error, the model the owner names.** [`modules/computer/error/`](../../computer/error/error.md) holds only `error.md` (`(software)-[:---]->(software_error)`), a `dt-uuid.kh` (`type UUID thing_p.UUID`) and two services. 2. **Which language and file kind?** Matters: Khayyam is the official language and the presumption is "everything is code, in Khayyam"; but the existing declarations are Python (`TaskKind`) and commented Go-in-`.kh` (`TODO(go-migrate)`), and Khayyam's own state decides whether a `.kh` set declaration is parseable today. Options: (a) Khayyam, accepting that it is a commented placeholder until converted, as `rule-status.kh` already is; (b) Python now, in the module, moved later; (c) Khayyam plus a Python reader that already works. 3. **What does a declared value contain?** Matters: it is the contract the storage layer reads. Today `LabelDefinition` = word + identifier + kinds; `LabelKind` adds summary, `read_by`, `normalize`. Options: (a) reuse that exactly; (b) add domain and version; (c) add `deprecated`/`replaced_by`. Default: (a) plus the domain, which is what makes it per-domain. **Agent** drafts, **Owner** confirms if the identity string changes.
4. **Where does the human text (name in each language, explanation) live?** Matters: Error keeps it in `locale.<lang>.kh` beside the value, and `text` is its own domain. 5. **Is a status a different thing from a label in the declaration?** Matters: research 001 tentatively says a status is a label of kind `Status` taken as a loop-edge plus a transition event; `status.md` says labels are checked async in rules, statuses sync in services. Options: (a) the declaration lists values only and a rule module states who may move between them; (b) the declaration lists permitted transitions as data. 7. **Does the declaration contain the Error-like "returns the values" function, or is the set itself the value?** Matters: the owner says "even if the code only returns the values". ### A. What a domain declares
1. **Unit of declaration — answered.** One file per set (option b), split to a file per value only when a value gains behaviour of its own (a transition rule, a check). Both precedents are one file per set: `status.py` holds eleven values with meaning, kinds and identifier; `task_kind.py` holds seven. §5 already allows the agent to choose (b). The Error precedent (one file per value) is a Go-era shape whose files carry nothing but an identity string, which a set file carries as well.
2. **Language and file kind — recommended — needs owner confirmation.** Khayyam cannot carry the values today: the Khayyam core's body reader states that "the grammar ships no control-flow keyword, no operator, and no literal of its own" ([`body.ts`](../../../bundles/khayyam/core/src/body.ts) lines 8–16), so a word or a UUID cannot be written in a `.kh` body; and a commented `TODO(go-migrate)` block such as [`rule-status.kh`](../../computer/rule/status/rule-status.kh) is read by no program, so it is not code in the sense of [A Fact in Code Is Written Once](../documentation/documentation.md#a-fact-in-code-is-written-once) — no check can fail on it. That rule permits another language: "code in another language, such as the Python of Memar's scripts today, is held to the same rule". Recommendation: (i) the **shape** — the abstraction a declaring set satisfies (question 7) and the registrar (question 8) — is written in Khayyam in `modules/knowledge/label/protocol/`, since abstractions are what the frontend already accepts ([label.handoff.md](label.handoff.md) Status line 9); (ii) the **values** of a vocabulary a program reads now are written in Python in the declaring module, as `status.py` is, until Khayyam has a route for literal values (its constants are capsule-returned values, [Encapsulation → Constants as Capsule-Returned Values](../../../docs/khayyam/encapsulation.md#constants-as-capsule-returned-values)); (iii) a vocabulary no program reads yet stays in its handoff as candidates (question 20). Owner decision 1 in [7](#7-owner-decisions-needed).
3. **Contents of a declared value — answered.** Reuse what the code already declares (option a): the word, the identifier (UUID v7), the kinds it takes (`LabelDefinition`, [`label.py`](../documentation/primitive/label.py)); a one-sentence meaning, as `status.py` and `task_kind.py` give every value; and for a kind, its summary, `read_by` and `normalize` (`LabelKind`). **No domain field and no identity string:** the declaring file's module path already says which domain declares the value, and a second copy is what [One Authoritative Location per Concern's Data](../../../docs/modeling.md#one-authoritative-location-per-concerns-data) forbids; the identity is the identifier ([label.md](label.md) line 10, "Names are labels; identity is not"), so the Error string `domain/…; package=…; name=…` is not carried over. `deprecated` / `replaced_by` waits on label handoff research question 23 (what happens to attachments when a label is merged, split or retired) and is not added now.
4. **Where the human text lives — answered.** In the type's own detail, one file per human language, beside the declaration: "A description in a human language of a code fact belongs to the type's own detail methods, not to a document, and each human language has a file of its own" ([documentation.md](../documentation/documentation.md) line 162). That is the Error shape (`locale.eng.kh`, `locale.per.kh` beside [`errors.kh`](../../computer/buffer/errors/errors.kh)); English meanings may stay inline until a second language arrives, as `status.py` states.
5. **Is a status a different thing from a label — answered for the declaration.** One shape (option a): the owner ruled on 2026-10-16 that Status values are labels of the label `Status` (`status.py` line 38), and [label.md](label.md) line 23 states it. What stays open is not the declaration but the behaviour around it — the transition event and the synchronous-read guarantee — which is label handoff research question 3 and question 6 below; it no longer blocks declaring statuses.
6. **Where transitions go — answered.** In the rule domain, not in the declaration (option a). [status.md](../status/status.md) line 13: "The move from one status to another is an event. A rule may allow or block that event. The rule lives with the event." [contract status.md](../../rights/contract/edges/status/status.md) Placement: "Transitions are rule decisions (core never knows Rule)". The owner's ruling R3 places `law/rules` beside `law/labels`, the same split. A declaration lists values; a rule module states who may move between them.
7. **A function or a constant — answered.** A pure function returning the definitions (option b), with no I/O. In Khayyam a constant *is* a value returned by a capsule method, with no separate `const` declaration ([Encapsulation → Constants as Capsule-Returned Values](../../../docs/khayyam/encapsulation.md#constants-as-capsule-returned-values), lines 141–148), so "code that only returns the values" is Khayyam's own form of a constant. In Python today it is a function or a class method returning `LabelDefinition`s, as `Status.for_kind` and `LABEL_KIND.closed` already return them.

### B. The seam to storage/memory
8. **Registration interface — answered.** Neither push from the domain nor an import of every domain by the memory layer: the label module owns a small protocol — a *declaring set* (returns its definitions) and a *registrar* (receives definitions, answers whether a label is defined) — and the **composition** that assembles a system hands each declaring set to the registrar it chose. The domain depends only on `label`; the memory implementation depends only on `label`; neither names the other. That is Memar's composition rule ([Modeling](../../../docs/modeling.md) line 11: independent concerns composed "at the composition layer, with no single fixed owning entity") and keeps the kernel rule that a kernel module never names a pluggable one ([kernel.md](../modularity/labels/kernel.md) line 19). Option (b) as written — the storage layer imports declarations — would make memory depend on every domain, the reverse direction.
9. **Storage or memory — answered.** Memory. [memory.md](../../computer/memory/memory.md) line 11 rejects "the ecosystem's two-name split of the field into 'memory' versus 'storage'" and treats every retaining capacity as memory classified by retention, which is the owner's own correction ("more correctly layer memory"). A registrar is therefore an implementation in the memory category (a record kept by `modules/computer/memory/record`, or a graph, or a file); `modules/storage` is not given a second, competing role. Whether `modules/storage` itself folds into memory is outside this question.
10. **Identifier stability — answered.** Option (a): minted once as UUID v7 by the tool (`new_id()`, [`label.py`](../documentation/primitive/label.py) line 52) and written into the declaration, never regenerated — exactly how `status.py` and `task_kind.py` carry `01a14a04-65…` identifiers. Option (b), deriving the identifier from domain and name, is rejected: the identifier would change when the word or the module is renamed, while [label.md](label.md) line 22 requires that "behaviour that must survive a rename is bound to identity and never to a label".
11. **What the search needs — answered, with one finding.** The search for every record that took a label needs only the identifier, which every plan carries as `word(identifier)`. But the registry's other field is read: `LabelRegistry.words` ([`label.py`](../documentation/primitive/label.py) lines 199–202) uses each definition's kinds to tell a topic from a task kind, and [`plan_labels.py`](../../process/session/services/plan_labels.py) `topics_of` (line 99) feeds `claims` batching (`claims.py` lines 116, 149, 169, 171, 181, 212) and `memar label list`. `resolve` (`label.py` lines 227–232) also reads the registry to give a word already used the same identifier. So any replacement must still give the `LabelRegistry` every definition with its kinds; a registry built from the declarations does, and the file is then unnecessary.
