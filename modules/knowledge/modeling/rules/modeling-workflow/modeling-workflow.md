# Modeling Rule — Modeling Workflow
A rule held for [Modeling](../../modeling.md), for discovering or reviewing a model.

## The rule
1. Extract concepts, responsibilities, constraints, and relationships; treat each as provisional.
2. Challenge candidates, audit nodes and relationships, and examine responsibility boundaries.
3. Identify independently responsible or changing concerns.
4. Delay implementation decisions until the graph stabilizes and material assumptions have been challenged.
5. Before code, state the owning module and its contract; record the questions this exposes. The exception is only code needed to make a language itself compile and run, and a session does not classify its own work as that exception.

## Why it exists
A model succeeds by improving understanding into stable concepts, relationships, and boundaries, not by producing implementation artifacts.
