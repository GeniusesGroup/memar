# Khayyam Rule — Receiver Method Names Handoff
Open state for [receiver-method-names.md](./receiver-method-names.md). See the repository's [documentation-handoff.md](../../../../docs/documentation-handoff.md) for what a handoff is.

## Status
Active — decided 2026-09-26 for the ported corpus, where 585 method declarations in 196 protocol files carried their owner's name and are now the owner's decision to settle file by file. One file is corrected: `modules/time/timer/protocol/timer.kh`.

## Decisions
- **A method no file imports keeps the bare name** — Decided (2026-09-26, owner). The receiver supplies the context: a timer inside another capsule is called through it, so the method is `Start`, not `Timer_Start`.
- **The conceptual shape is not a spelling** — Decided (2026-09-26, owner). `socket.Timer().Start()` states the idea and is explicitly not valid Khayyam; the rule cites the language document for the real form rather than adopting the shape.
- **The condition is empirical, not linguistic** — Decided (2026-09-26). Of the 585 owner-prefixed method names in the corpus, none is brought in by an `in`, so all 585 fall under the rule; a repository that imports a method by name does not.
- **A bare method name wins over a declaration's plain name** — Tentative (2026-09-28, derived from [Abstraction → Abstraction Realization](../../../../docs/khayyam/abstraction.md#abstraction-realization-implicit-satisfaction); awaiting the owner's review). Satisfaction matches methods by name, so a method prefixed to escape a collision forces the prefix on every realization and splits one operation across prefixes; the declaration is qualified instead, under the [qualified names rule](../qualified-names/qualified-names.md). `Domain` on `BS_Init_Request` returns `App_Domain`; `Type` and `Status` on `GUI_Element` return `GUI_Element_Type` and `GUI_Element_Status`. Rejected: the bridge's `member-qualified-for-collision` direction (219 methods in the dry run), and the reverse proposal of dropping the qualifier from the 68 abstractions whose bare name is a method name. Answers the open question formerly recorded here as “whether a bare method name may equal a declaration's name”. Its premise — a method's name is what every realization writes, so it carries no owner — is the owner's own reason in the field-accessor decision below; the direction of a collision between a method and a declaration stays tentative.
- **A field abstraction's method is named for the value it returns** — Decided (2026-09-29, owner). The owner's ruling on `modules/net/uri/protocol/scheme.kh`: `URI_Field_Scheme_Scheme` is strange, and because a field abstraction's methods are implemented by other capsules the name can simply be `URIScheme`. The corpus check shows no other owner's `Scheme` method and no second scheme field, so the accessor is `Scheme`; `URIScheme` is the rule's answer once either exists. The qualifier comes only from the field's own name or its value, never from a module path segment the field does not carry (`FileMetadata` and `DirectoryMetadata`, `SocketStatus`, `RequestedAt`). Applied by `abstraction_bridge.py field-names`: 90 methods renamed. Answers, for field accessors, the question formerly left implicit here of whether a field method keeps its `<owner>_<field>_<name>` spelling.

## Open Questions
- **The field accessors whose value name is already a declaration.** `BlockNumber` on `Field_BlockNumber` returns a `BlockNumber`, and the declaration `BlockNumber` holds the name. Under the Tentative decision above the method would take the bare name and the declaration would be qualified, which is not applied while that direction awaits the owner. Meanwhile only the owner part follows the renamed field: `Field_BlockNumber_BlockNumber`, `Field_PageNumber_PageNumber`, `Field_MemoryAddress_MemoryAddress`, `Field_ThreadID_ThreadID`, `Field_CompressLevel_CompressLevel`, `Field_JSON_Length_JSON_Length`, and `Field_Syllab_Lengths_Syllab_Length`. Left entirely as written: `Field_Time_Time`, `Field_URI_URI`, `Field_Error_Error`, `Field_Service_Service`, `Field_DataType_DataType`, `Field_Conditional_Conditional`, `Field_DayEpoch_DayEpoch`, `Field_HourEpoch_HourEpoch`, and `Field_SecondEpoch_SecondEpoch`. These names are reports, and they wait on the owner's review of that decision.
- **Whether the two variable groups are written when the receiver is an abstraction.** The method document writes both groups for every call it spells out, while the polymorphism document's abstraction example is the single-group `h.Hash(data)`. Nothing states whether the influenced group is written for an abstraction receiver, so the rule cannot yet give the exact call for a timer that arrives as an abstraction value.
- **Whether one unit may hold the same bare method name under two owners.** The question belongs to the language document and is carried in [Method in Khayyam Handoff → May one unit declare the same method name under two owners?](../../../../docs/khayyam/method.handoff.md#may-one-unit-declare-the-same-method-name-under-two-owners). What this rule records meanwhile: the bridge resolves the case conservatively — the first method keeps the bare name and the second is emitted as `<owner>_<name>` with a `member-qualified-for-collision` entry in the run report, so the two never collide. That output is a report and not a name: satisfaction matches by name, so the prefixed second method no longer satisfies an abstraction that requires the bare one. A field abstraction's method no longer takes that path: it takes the field's own qualifier (`FileMetadata`), and only a counter remains as the report when no qualifier is free.
- **Whether the rule should become a gate rather than a review convention.** Nothing in the toolchain reads method names: the M1 frontend resolves imports and type references, not the shape of a name. A rule that reports a method repeating its owner is not written; the enforcement class is unsettled, and this rule states a convention a reviewer applies, like the [qualified names rule](../qualified-names/qualified-names.md).
- **How a method that a file *does* import should be named.** The rule's condition excludes such methods, and the [qualified names rule](../qualified-names/qualified-names.md) says the name carries its module at the definition site. Whether an imported method takes the bare name, the owner-prefixed name, or the module-qualified name is not stated by either rule.
