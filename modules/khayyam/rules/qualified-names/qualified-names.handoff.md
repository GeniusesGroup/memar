# Khayyam Rule — Qualified Names Handoff
Open state for [qualified-names.md](./qualified-names.md). See the repository's [documentation-handoff.md](../../../../docs/documentation-handoff.md) for what a handoff is.

## Status
Active — decided 2026-09-25 with the ported corpus, where 1021 declarations and methods were renamed and 0 cross-file collisions remain. Extended 2026-09-28 with the method-name collision and the pairs qualification cannot separate; the extension is tentative until the owner reviews it, and it has been applied to no `.kh` file. Extended 2026-09-29 with the field shape, which the owner ruled and which is applied: 86 field abstractions renamed across `modules/` (outside `modules/khayyam/`), 24 cases left as reports. As of 2026-10-01 this rule is on the port's critical path: `reemit` refuses to write any of the five names below until it is given an answer, and that refusal is what stands at `written 87` and `guarded 342` of 470 targets.

## Decisions
- **Names are qualified at the definition site, not at the import site** — Decided (2026-09-25, owner). The language supplies no `as`, so a name that meets another must already say where it lives; a wrapper or an adaptor at the import site preserves the duplicated abstraction, which the language document names the wrong fix.
- **A name that already carries its module steps up rather than shortening** — Decided (2026-09-25, owner). `Duration` in `time/duration` is `Time_Duration`, not `Duration` shortened and not `TimeDuration` invented by transliteration.
- **A declaration whose plain name is a bare method name is qualified; the method stays bare** — Tentative (2026-09-28, derived from [Abstraction → Abstraction Realization](../../../../docs/khayyam/abstraction.md#abstraction-realization-implicit-satisfaction); awaiting the owner's review). Satisfaction matches methods by name, so a method name is part of the contract every realization repeats, while a declaration's name is where qualification already puts context. Rejected: the bridge's current direction, which gives the declaration the bare name and prefixes the method (`member-qualified-for-collision`) — it bakes the owner's name into every realization and splits one operation across prefixes. Consequence for the corpus: the 68 abstraction renames the reemit dry run proposes into a bare name that is also a method name (`Domain`, `Status`, `Name`, `Clone`, `Hash`, …) are not applied; those abstractions keep their qualified names.
- **A counter, or a step up the path that the name does not call for, is not a name** — Tentative (2026-09-28; awaiting the owner's review). `GUI_Event_2`, `Net_Socket_2`, `Net_PacketTarget_2`, `Net_PacketListener_2`, the `_2` capsules of `gui`, and `Storage_UUID` beside `Record_UUID` are the tool's reports of a pair it could not separate. The rule's main document classifies such a pair as one concept declared twice, an abstraction and a capsule named alike, or one source declaration emitted twice, and gives each its answer.
- **Between an abstraction and a capsule that one module's path names alike, the abstraction keeps the name** — Tentative (2026-09-28, derived from [Abstraction → What You Cannot Do](../../../../docs/khayyam/abstraction.md#what-you-cannot-do) and [Satisfying an Abstraction](../../../../docs/khayyam/abstraction.md#satisfying-an-abstraction); awaiting the owner's review). Abstraction signatures and compositions may name only abstractions, so the abstraction's name is the one the corpus writes. Rejected: renaming the abstraction and leaving the capsule the name, which is what the TODO in `modules/gui/protocol/event.kh` (“pick the protocol's real name”) assumed; it moves the name every importer writes in order to keep the one only a constructor writes.
- **An observer abstraction is `Observer_<concept>`, qualified after `Observer_` only when the corpus makes the concept ambiguous** — Decided (2026-09-29, owner). The owner's ruling on `modules/net/uri/protocol/scheme.kh`: `URI_Field_Scheme` was a poor name, `Field_URI_Scheme` better, and `Observer_Scheme` best if `URI` only repeats. Applied by `abstraction_bridge.py observer-names`. Family prefix `Field_`/`Method_` superseded by `Observer_`/`Mutator_` same day; see [observer and mutator handoff](../../../computer/adt/rules/observer-mutator/observer-mutator.handoff.md).

## Open Questions
- **Whether the rule is a governance rule or a source-rewrite one.** As stated it is a convention a reviewer or a checker asserts over a repository. Under the accepted rule model it could instead be a `source-rewrite` rule — the engine qualifying names as it rewrites — which would make the port's `reemit` mode a rule's output rather than a developer tool. The model is provisional, so the class is unsettled.
- **Whether a qualified name resolves.** The toolchain accepts `pkg.Type` without a binding check, so this rule produces names the toolchain cannot verify. Whether a qualifier denotes a module, a package, a directory, or a file is undecided, and the rule's own output depends on the answer — the port qualified by module path, which is a convention this repository chose rather than one anything requires.
- **Whether a collision is always a report.** The rule reports a collision; it does not say the report is an error that blocks. An organization might treat a collision in a leaf module as acceptable, and where that line falls is a choice the rule currently makes implicitly.
- **Whether the bridge has an expiry.** The language's position is that qualification is a stopgap on the way to one abstraction owning one concept. Nothing tracks which qualified names have already been redesigned and which have not, so "stopgap" has no accounting.
- **Which side of a collision between distinct concepts keeps the plain name.** Read literally, the rule qualifies every declaration whose plain name collides, which would qualify both sides. The rule's own example and the corpus do otherwise: `Stringer` stays bare in `codec/string` while `UTF8_Stringer`, `ASCII_Stringer`, and `Time_Stringer` carry their modules; `Event` stays bare in `process/event` while `GUI_Event`, `Race_Event`, and `ProcessLog_Event` do. The declarations that keep the plain name are the general ones the others compose or specialize, and the ones that existed before the port — but no document states either criterion. The final spelling of `Stringer`, `Stringer_To`, and `Stringer_From` depends on the answer; nothing is renamed until it is given.
- **Which module owns a concept declared twice.** `Record_UUID`, `Field_RecordUUID`, and `Field_RecordsUUID` are declared identically in `identifier/record` and `memory/record`. The names are fixed by the rule whichever module keeps them; the owner is not. For `identifier/record`: [Lib → What does not belong here](../../../lib/lib.md#what-does-not-belong-here) places identity under `modules/identifier/`, and the module's path says it is a record's identifier. For `memory/record`: all five files that include any of the three today include the `memory/record` copy, and the `identifier/record` copy has no importer. Owner ruling; then one declaration is deleted and its importers repointed, as one change. Until then the field shape leaves them as they are written — `Record_Field_RecordUUID`, `Record_Field_RecordsUUID`, `Storage_Field_RecordUUID`, `Storage_Field_RecordsUUID`, and their accessors — because both module paths name them `Field_RecordUUID` and `Field_RecordsUUID`.
- **Whether `Boolean` is a naming-table entry rather than a decision.** `reemit` reports `Boolean` unresolved with claimants `math/boolean` and `math/boolean/protocol`, and refuses to write it. The two are not one concept declared twice: the reference declares `type Boolean bool` in `math/boolean/boolean.go:14` and `type Boolean[B any] interface` in `math/boolean/protocol/boolean.go:17`, a capsule and an abstraction, and the corpus has already separated them — `modules/math/boolean/boolean.kh` declares the capsule `Bool` and says so in its own comment ("Bool is an implementation, not the contract: a contract that needs a truth value names the abstraction `Boolean`"), while `modules/math/boolean/protocol/boolean.kh` declares `tp Boolean ab`. So the corpus is not ambiguous here; the port's table is, because it maps both Go declarations to `Boolean`. Told that the capsule's name is `Bool`, the collision disappears and one of the five unresolved names is a table entry rather than an owner ruling. Confirming that `Bool` is the name the owner wants is the part that is a decision. Evidence: the live `reemit --dry-run` report of 2026-10-01 (`declarations 468 renamed 138 unresolved 5`), the two Go declarations, and the two `.kh` files.
- **What a capsule that gives up its name to an abstraction is called.** The abstraction case leaves the capsule to its author, and no document states a convention for a module's own realization of its own abstraction. The corpus waiting on it: the `gui` capsules now written `GUI_Application_2`, `GUI_Page_2`, `GUI_Pages_2`, `GUI_Navigator_2`, `GUI_History_2`, `GUI_Information_2`, and `GUI_PageState_2`, the capsule written `GUI_Event` in `modules/gui/event.kh`, and the unported `net` realizations of `Socket`, `PacketTarget`, and `PacketListener`. Owner ruling — per capsule, or a convention stated here.
