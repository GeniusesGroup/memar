#### What changed
- Adopted `modules/process/sync/` as the home of the synchronisation responsibility, the folder already holding three declarations and no document, and stated the responsibility, the membership criterion, the four exclusions, and the condition under which the module would split.
- Modelled two concepts — **Atomic Operation** and **Sequencing** — with what each owns and does not, and the relations between them: that an atomic operation establishes nothing about order on its own, and that a guarantee is stated by one party and relied on by another without either stating it for the other.
- Refused **Mutual Exclusion**, **Concurrency**, and **Shared State** as concepts of this module, each on a document that already holds the ground: exclusion as a mechanism Process declines to let become the default representation, concurrency as [Concurrency Realization](../../computer/concurrency/concurrency.md)'s own stated boundary, and shared state as the occasion rather than the responsibility.
- Recorded that **an atomic head-or-tail advance is not sufficient to free a region**, working out the five things a buffer method doing it needs and stating that this module supplies two of them; the cursor and its meaning are the buffer's, the contract terms are a crossing's, and the relaxability is an organization's.
- Recorded what the language and protocols already state in seven items, what neither states in four, and that the one protocol document whose abstract claims to state the synchronization primitives states none — which is why the module holds no `rules/` folder and writes no declaration.
- Recorded the code the module would hold, what it will wait on, and what it must wait on.
- Refused the names `Mutex`, `RWMutex`, `WaitGroup`, `Once`, `Lock`, `Locker`, `Concurrency`, `Visibility`, `Publication`, `Memory Order`, `Strict Consistency`, `Sequentially Consistent`, `Linearizable`, and `Race` as this module's vocabulary, with the owner each already has.

#### Considered and not done
- **Mutual Exclusion kept as a third concept, on the strength of the two lock declarations the folder already holds.** The folder's own contents argue that exclusion belongs here, and keeping it would have made `Locker` and `ReadLocker` in-membership rather than residue. Rejected because [Process → Concurrency](../process.md#concurrency) at `:200` states that locking "is not the definition of concurrency and should not become its default representation", `:220` places it at the end of a chain whose earlier steps may resolve the concern without it, and [Agency → Agency Before Synchronization](../../../docs/agency.md#agency-before-synchronization) at `:602` requires that a mechanism not become the model of responsibility itself; a module holding a guarantee and the mechanism that supplies it holds two responsibilities under one name. The two declarations stay on disk untouched, and the split condition is stated so a ruling that puts exclusion in scope produces a peer folder rather than an extension.
- **A `rules/` folder written first, against this document as its own normative claim.** The condition a governance check would enforce is the most valuable thing this module could add to the repository, and writing the Rule would have made the check real sooner. Rejected because [Rule → Normative Claim and Executable Form](../rule/rule.md#normative-claim-and-executable-form) at `:66` requires a Rule to cite the document owning its claim, and no document states that an indivisible, ordered step exists; a Rule citing the module that realizes it would make the implementation the authority for the protocol, inverting [Protocols → Where implementations live](../../README.md#where-implementations-live).
- **The folder renamed to `synchronization/` in this session.** `sync` is one ecosystem's package name for a set of mechanisms, and [Documentation → File Naming](../../../modules-plugable/knowledge/documentation/documentation.md#file-naming) requires a name to avoid implementation-specific vocabulary, on the precedent the [Binding Model → Foreign Function Interface](../../computer/binding/binding.md#foreign-function-interface) sets by refusing `ffi`. Rejected for this session because the move is three `.kh` files and three citing files - [`docs/protocols/process/event.handoff.md`](../event/event.handoff.md), [`modules/memory/page/protocol/page.kh`](../../computer/memory/page/protocol/page.kh) and [`modules/process/event/race-event-target.kh`](../race/race-event-target.kh) - and this session writes no `.kh` file and runs no git command. The rule requiring the move is [`modules/README.md:11`](../../README.md) and the move is carried as owed.
- **A `README.md` written as a real file, carrying the module's responsibility and membership criterion.** That is what `modules/process/test/README.md` and `modules/process/error/README.md` are, and this folder had no document at all. Rejected because this document is the folder's main document under [Documentation → File Naming](../../../modules-plugable/knowledge/documentation/documentation.md#file-naming), and [Documentation Practice → Folder READMEs](../../../modules-plugable/knowledge/documentation/documentation.practice.md#folder-readmes) requires such a folder's `README.md` to be a symbolic link to it, recorded as git mode `120000`; a real file beside a main document is a text file pointing at a sibling. The README is carried as owed, alongside the same debt in `modules/computer/binding/` and `modules/process/control-flow/`.
- **`Visibility` as the name for the ordering guarantee.** It is the word a reader reaches for first, and this repository uses it in two other senses rather than as an owned term of its own. Rejected because [Encapsulation → Sovereign Encapsulation](../../../docs/khayyam/encapsulation.md#sovereign-encapsulation) at `:71` already uses it for the absence of a visibility modifier and [Khayyam → Self-Documenting Code and Naming](../../../docs/khayyam/khayyam.md#self-documenting-code-and-naming) at `:185` for architecturally visible computation; one word, two referents, which [Khayyam → Import Mechanism](../../../docs/khayyam/khayyam.md#import-mechanism-in) calls an architecture error. `Publication` and `Memory Order` were rejected on the same ground, the first being this repository's research sense and the second one ecosystem's term for a strength nothing here has ruled on.
- **Ordering folded into Atomic Operation as a required contract term rather than modelled as a second concept.** That is a smaller model and it keeps the module to one concept. Rejected because ordering has its own rule - that a step another party relies on must be ordered before that party's read of it - its own lifecycle, and no statement anywhere in this repository, so folding it in would leave the ring's actual requirement unstatable while appearing to have been stated. Two concepts that answer one question are one responsibility; two that answer different halves of it are not, and indivisibility without order is the case [Process → This Document Treats Concurrency as One Concept, Not Two](../process.md#this-document-treats-concurrency-as-one-concept-not-two) at `:228` says needs no second core to arise.
- **A declaration written now for the indivisible step, over the body-less capsule-owned method the language already admits.** The form is stated by [Khayyam → Method](../../../docs/khayyam/khayyam.md#method) at `:91`, so a per-concern declaration is writable today. Rejected because it would state a decision this module has not made: the guarantee it names has no owner in any protocol, and [`modules/process/test/README.md`](../test/README.md) gives this repository's own reason - "writing declarations for a mechanism that has no agreed contract would state a decision this module has not made".
