# Synchronization Model Handoff
Open work for [sync.md](./sync.md). Entries are mutable current state — revised as each item moves, removed when it resolves or is dropped. Every open question below names the file and the section it can be read at, so a session that starts cold can go straight to it. See the repository's [documentation-handoff.md](../../../modules-plugable/knowledge/documentation/handoff/handoff.md) for what a handoff is.

## Topic & Purpose
The model of **synchronization** — the responsibility by which two activities that may progress at the same time are given a dependable statement of when each one's effect on state they both touch has taken effect — and the statement of what the implementation module under [`modules/process/sync/`](./) is for. The module was adopted in place where it already stood rather than created, and the model settles: that the responsibility has two guarantees and not a third (**Atomic Operation** and **Sequencing**, with exclusion refused on [Process → Concurrency](../process.md#concurrency)'s own ground); that the owner's ruling places the indivisibility of a ring's release on **a method of the buffer module** that obtains this module's guarantees; that **atomicity alone does not free a region**, so the owner's word carries one of the two halves the ring needs and the other half is stated by no document in this repository; that the module holds no `rules/` folder because its normative claim has no home document; and that nothing here is implementable today as a guarantee, only as a body-less declaration whose implementation arrives from outside. It settles no signature, no method name, and no per-target realization, because each of those turns on a question carried below rather than on one this session answered.

- **`modules/process/sync/` is this module's home, and it is adopted where it stands with a rename owed** — Decided. The folder already held three declarations under [`protocol/`](./protocol) and no document, which [`modules/README.md:10`](../../README.md) makes "a decision made visible" rather than an absence and `:12` makes a folder whose intent is carried by its name until a README states it. The intent in the name is synchronisation primitives, which is what the owner asked for, so this is the same responsibility under a name that should change rather than a different module. **The rule that requires the change** is [`modules/README.md:11`](../../README.md) — "no folder here is final. Names may be merged, split, moved, or retired whenever the responsibility they name is better served another way" — together with [Documentation → File Naming](../../../modules-plugable/knowledge/documentation/documentation.md#file-naming)'s requirement that a name "avoids implementation-specific vocabulary", on the precedent the [Binding Model → Foreign Function Interface](../../computer/binding/binding.md#foreign-function-interface) sets by refusing `ffi` as one ecosystem's word. **What was done about the old path:** nothing was moved. The rename would require three `.kh` files to move and three files to be repaired — [`docs/modules/process/event.handoff.md:7`](../event/event.handoff.md)–`:8`, [`modules-plugable/computer/memory/store/page/protocol/page.kh:15`](../../../modules-plugable/computer/memory/store/page/protocol/page.kh) and [`modules/process/event/race-event-target.kh:6`](../race/race-event-target.kh) — and this session writes no `.kh` file and runs no git command, so the whole document addresses the module by its present path and carries the move as owed. This mirrors what the Binding Model did on 2026-10-03, where the rename was made and the links repaired in one session; here the second half is not available.
- **The responsibility has two guarantees, and exclusion is not one of them** — Decided, and the decision the folder's existing contents had to be measured against. **Atomic Operation** is an effect no other activity observes part-way; **Sequencing** is the order in which one activity's completed effects become another's next premise. **Mutual Exclusion** is refused as a concept of this module on [Process → Concurrency](../process.md#concurrency) at `:200` — "Locking is one possible mechanism for satisfying a concurrency constraint; it is not the definition of concurrency and should not become its default representation" — and at `:220`, which places it at the end of a chain whose every earlier step may resolve the concern without it, with [Agency → Agency Before Synchronization](../../../docs/agency.md#agency-before-synchronization) at `:602`–`:604` adding that a mechanism must not become the model of responsibility itself. **Rejected:** making exclusion a third node, which would give the module a second responsibility under one name and reproduce the shape the owner refused when refusing `os`; and refusing exclusion *and* sequencing as one "mechanism" category, which would leave the module with one concept and no way to state the ring's requirement.
- **Atomicity alone does not free a region; the ring needs ordering and this repository states none** — Decided, and this session's sharpest finding. The application's advance of the head is what says a portion is free; what makes refilling it safe is that the application cannot advance the head before its own writes to the portion have completed, **and** that the driver cannot observe the advanced head before those writes are visible to it. A store that is indivisible but unordered delivers the second without the first. This is why the two guarantees are separate concepts and why [Process → This Document Treats Concurrency as One Concept, Not Two](../process.md#this-document-treats-concurrency-as-one-concept-not-two) at `:228` matters operationally rather than terminologically: a ring that is correct on one core and wrong on two is not a parallel-only hazard. **What it costs the owner's design:** the word "atomically" carries one of the two halves, and the half it does not carry has no home document.
- **The indivisibility of a ring's release is a method of the buffer module that obtains this module's guarantees** — Decided, as the owner's ruling, recorded here so that a later session does not re-open it. The owner: atomicity is carried by "a method of the buffer module, using a module similar to Go's `sync`", and the module itself may be generated. **What the model adds to the ruling** is the working-out at [What an atomic head-or-tail advance needs from this module](./sync.md#what-an-atomic-head-or-tail-advance-needs-from-this-module): the method needs five things and this module supplies two of them. The cursor and its meaning are the buffer's, under [Modeling → Constraints Belong to the Constraining Concern](../../../docs/modeling.md#constraints-belong-to-the-constraining-concern); the terms saying how long a portion is valid and what each side may assume about the region are a crossing's, and no document owns them; the relaxability of the whole is an organization's, per [Memory → Safety enforcement is governance](../../computer/memory/memory.md#safety-enforcement-is-governance) at `:85`. **What it awaits:** the protocol question below, and the naming of the method and its cursor.
- **The module holds no `rules/` folder today** — Decided, and the reason is structural. [Rule → Where Rules Live](../rule/rule.md#where-rules-live-rules-beside-protocol) at `:66` requires a Rule to cite the document owning its normative claim, and the one condition this repository would want here — a method that advances a shared cursor states that it is indivisible and states the order it establishes — has no document to cite, because [Concurrency Realization](../../computer/concurrency/concurrency.md) at `:11` claims to cover the primitives its body never states. [`modules/process/test/rules/`](../test/rules/) and [`modules/computer/adt/rules/`](../../computer/adt/rules/) each hold rules whose claims their protocol states, which is the condition this module does not meet. **Rejected:** writing the Rule first against this model as its own claim, which would make a module the protocol's own authority and invert [Protocols → Where implementations live](../../README.md#where-implementations-live).
- **The two lock declarations stay on disk and are excluded** — Decided. [`protocol/locker.kh`](./protocol/locker.kh) and [`protocol/read-locker.kh`](./protocol/read-locker.kh) are residue, which the owner has ruled neither evidence nor a premise, so their presence says nothing about the responsibility and their absence would be an edit this session has no warrant for. The module's membership criterion excludes them and the exclusion is carried as a question for the owner below. **What was not done:** no `.kh` file was edited, moved, or deleted.

## Ambiguities Resolved
- **Is `modules/process/sync/` this module, a different one, or the same responsibility under a name that should change?** — Answered: the same responsibility under a name that should change. The folder's intent, read from its three declarations and from [`modules/README.md:12`](../../README.md), is synchronisation primitives, which is the module the owner asked for; `sync` is Go's package name for a set of mechanisms rather than the name of the concern. The rename is owed and is recorded under Decisions above with the links it must repair.
- **Can a Khayyam source express an indivisible update at all?** — Answered: yes, as a declaration and as nothing else. [Khayyam → Method](../../../docs/khayyam/khayyam.md#method) at `:91` and [Method in Khayyam → Body-less Methods](../../../docs/khayyam/method.md#body-less-methods-ffi-and-contracts) at `:80` make a body-less method on a concrete capsule the form through which an implementation arrives externally, and [Agency in Khayyam](../../../docs/khayyam/agency.md#concurrency-decisions-as-agency-not-syntax) at `:13`, `:39` and `:44` is why no source computes, writes, or inspects one. What a source may therefore say is that advancing a cursor is one indivisible step whose execution arrives; what it may not say is anything about how.
- **Is a lock this module's business?** — Answered: no, and not because locks are unimportant. [Process → Concurrency](../process.md#concurrency) at `:200` and `:220`, and [Agency → Agency Before Synchronization](../../../docs/agency.md#agency-before-synchronization) at `:602`–`:604`, place exclusion as a mechanism a party reaches for after the responsibility question, and the module's own guarantees may be obtained without it — [process.md:232](../process.md#concurrency) records that pinning a bounded part of a process to one fixed Worker resolves a hazard without a lock. The two declarations' own comments confirm the mechanism-first reading: [`locker.kh:6`](./protocol/locker.kh) makes the contract depend on the substrate's `yield`, which [`agency.md:39`](../../../docs/khayyam/agency.md#concurrency-decisions-as-agency-not-syntax) assigns to the framework and the runtime.
- **Is race detection this module's business?** — Answered: no, and the repository already owns it. [`modules/process/race/`](../race/) holds a static detector ([`protocol/detector.kh:14`](../race/protocol/detector.kh)), a report event carrying a thread identifier and a stack ([`protocol/event.kh:9`](../race/protocol/event.kh)–`:10`), and a sanitizer, while [Memory → Safety enforcement is governance](../../computer/memory/memory.md#safety-enforcement-is-governance) at `:85` places data races among checks an organization may relax. Detection observes what happened; this module supplies what was guaranteed.
- **Is "visibility" the repository's word for the second guarantee?** — Answered: no, and the word is taken twice over. [Encapsulation → Sovereign Encapsulation](../../../docs/khayyam/encapsulation.md#sovereign-encapsulation) at `:71` uses it for the absence of a visibility modifier, and [Khayyam → Self-Documenting Code and Naming](../../../docs/khayyam/khayyam.md#self-documenting-code-and-naming) at `:185` for computational behaviour being architecturally visible. `Publication` is the research sense at [protocol.md:65](../../../docs/protocol.md) and `:143`. `Sequencing` is used because it is unreferenced and therefore carries its general meaning per [Terminology → The Default Meaning of an Unreferenced Term](../../../docs/terminology.md#the-default-meaning-of-an-unreferenced-term).

## Assumptions
- **The owner's "atomically" means indivisible of execution, not syntactic atomicity** — Stability: Strong. The sentence it comes from is about a head or tail changing so a portion is freed, which is an execution claim, and the same document records that the word is used of syntax elsewhere ([Khayyam → Syntactic Atomicity](../../../docs/khayyam/khayyam.md#syntactic-atomicity-and-semantic-clarity) at `:234`–`:235`). What changes it: an owner ruling that the owner meant the syntax sense, which the sentence does not support. Mitigation: the collision is recorded in this model and in the Binding Model rather than resolved by assertion.
- **The concurrency protocol will gain a synchronisation section rather than the guarantee moving to the memory protocol** — Stability: Weak. [Concurrency Realization](../../computer/concurrency/concurrency.md) at `:11` claims the scope and does not fill it, which is the strongest available evidence for the first; the second is available because [Memory](../../computer/memory/memory.md) at `:99`–`:102` already obliges the terms and is the natural owner of the memory semantics but has said nothing about ordering. What changes it: a ruling that the concept belongs to Memory, which moves this module's normative claim and its Rules with it. Mitigation: both candidates are named in the open question above rather than one being assumed.
- **The buffer module will own the cursor** — Stability: Weak. [`modules/README.md:11`](../../README.md) says no folder here is final and that names may be merged, split, or retired, so today's placement is a reading. What changes it: a restructure of `modules/computer/`, or a ruling that the cursor is a container concern and belongs to `modules/computer/adt/`. Mitigation: the model states which concern owns the *rule* about when a portion is free — the ring — and leaves the folder's fate to [`modules/README.md`](../../README.md)'s own rule.
- **The owner keeps a shared ring rather than falling back to the memory protocol's default copy** — Stability: Unexamined. The owner's design asks for zero-copy carriage and the memory protocol's default at [`memory.md:105`](../../computer/memory/memory.md#the-boundary-copy-convention-stated) is a copy. What changes it: an owner ruling that the boundary copy convention holds for a shared ring, which would remove the synchronisation requirement from this design entirely and leave the module serving other needs. Mitigation: the three terms the deviation obliges are named in the model, so the ruling has something to rule on.
- **A second organization will not need a different notion of what an indivisible step guarantees** — Stability: Unexamined. Every claim here is stated once and language-independently, which is what [Protocols → the specifications here remain language-independent](../../README.md#where-implementations-live) requires of a protocol, but nothing here has been read by a second organization. What changes it: a second realization disagreeing about whether the order is absolute or party-relative, which is the sub-question this model could not answer. Mitigation: the sub-question is stated as part of what a ruling must decide rather than assumed either way.
