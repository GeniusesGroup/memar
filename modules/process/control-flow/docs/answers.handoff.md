The base document holds each answer with its citations; this file holds what a session needs that the base document deliberately does not — the state of each remaining question, the assumption each answer rests on, and the defects found outside this folder that no session has yet fixed. ## Status

## Decisions
- **Every question was answered by reading, and none was answered by choosing** — Decided. Each of the nine was put to the language documents first, then the protocol, then the `.kh` corpus, then the toolchain's measurements, in that order, because that is the repository's own division of subjects. Reason: a question answered by argument would harden into a second authority over the same subject, and the one thing this session can settle without the owner is which questions the evidence cannot settle at all. A question the evidence does not settle is carried below with the sentence that would have to be written, so the next session can write that sentence rather than re-derive the search.
- **Silence is reported as a named absence, never smoothed into an answer** — Decided. Where no document states something, the base document names the document, the section, the sentence that would be needed, and the other document that would change with it. Reason: [Documentation → Content Rule](../../../docs/documentation.md#content-rule-no-fabricated-or-redundant-provenance) requires that an unknown be "stated as unknown or omitted, never glossed over with a confident-sounding filler", and a gap that reads as an answer is worse than a gap that reads as a gap — the first gets built on, the second gets closed.
- **Corpus witnesses are cited as declarations, not treated as rulings** — Decided. Where the only evidence for an answer is what some `.kh` file or some test fixture writes, the base document says so and names the file and line. Reason: the one measured realization of a two-branch contract in this repository survives as a compiled build product under `modules/khayyam/targets/js/build/`, its source absent, and a build product cannot be an authority over a protocol. `modules/khayyam/targets/js/target.md` says the same of its own artifacts at [The artifact of one unit](../../khayyam/targets/js/target.md#the-artifact-of-one-unit): "It is a build product and never a source of truth: the semantic representation is."
- **The nine questions are one decision wearing several hats, and one of them gates the rest** — Explored-but-unresolved. The first, the second, the third, the seventh, and the ninth questions cannot be answered independently: the owner of the forms, the type of its scope parameter, and the type that owns the two-branch contract are one signature. Reason: the pair's members must name a scope (`docs/protocols/process/control-flow.md:59`), a branch scope is the `sc` subtype (`docs/khayyam/khayyam.md:128`), an `sc` is a Scope rather than an Abstraction (`docs/type.md:181`), and an Abstraction's method signature may name only Abstractions (`docs/khayyam/abstraction.md:101`). What is unresolved is the owner's preference between closing that by admitting a Scope in an Abstraction's signature and closing it by making the library's owner a concrete capsule, which `docs/protocols/process/control-flow.md:130` makes the loss of replaceability. Rejected as a resolution path: declaring the forms on a capsule now and treating the protocol's Linter-governance claim as satisfied — that claim is about a library an organization can mandate, which is not what a capsule fixed in this repository is.
- **No question was carried forward from this session's own reasoning** — Decided. Every sentence in the base document is cited to a document line or a declaration, and the four that have no such citation are marked as conflicts or as absences. Reason: the base document is an Explanation-facet document and [Relevance discipline](../../../docs/documentation-explanation.md#relevance-discipline) admits a claim into the body only where reading it changes the reader's understanding of the design as it stands; an unreferenced inference would be this session's opinion wearing a document's clothes.

## Assumptions
- **A scope may be written in a signature if a document says so** — Stability: Strong. The grammar already admits an `sc` in an influencing group (`docs/khayyam/method.md:71`) and already admits a type-level argument for `sc` (`docs/khayyam/khayyam.md:132`), so nothing structural stands in the way; what is missing is the sentence. - **The absence of a scope parameter's type in the language documents is a gap and not a deliberate delegation** — Stability: Weak. `docs/khayyam/method.md:71` enumerates the three forms an influencing group may receive and then does not say how a scope's own is written, and `modules/khayyam/targets/js/target.handoff.md:50` reads the same absence. What changes it: a sentence in `docs/khayyam/khayyam.md#scope` or `docs/khayyam/method.md` delegating the spelling to the realization, which would make the toolchain's reading the standing one and this repository's answer to the question would be "whatever an organization states".
- **The JavaScript target's fixture is a faithful record of what `lib/control-flow.kh` declared** — Stability: Weak. It is the fixture a compiler test compiles, and the stored representation at `modules/khayyam/targets/js/build/.cache/modules_khayyam_targets_js_lib_control-flow.kh.json` agrees with it declaration for declaration, so the two corroborate each other. What changes it: evidence that the fixture and the built artifact diverged from the source, or that the source changed after the last build.
- **A removed source's declarations are not an authority over the protocol** — Stability: Strong. `modules/khayyam/targets/js/target.md` says so of every artifact it writes, and the removal at `modules/khayyam/targets/js/target.changelog.md:57` carries a reason — "a library belongs with the rest of the library under `modules/`, and a model settles before code is written". - **`Conditional` in `modules/math/logic/` is a Flow Decision outcome enumeration or an unrelated logic value, and not a third option** — Stability: Unexamined. Neither reading has been tested against `docs/protocols/math/math.md#realization-membership` or against what `modules/math/logic/conditional.observers.kh` would mean under each. What changes it: an owner ruling of `modules/math/logic/` — or a finding that a third reading exists, in which case the base document's fifth answer is incomplete rather than wrong.
- **The nine questions in `model.handoff.md` are the complete set** — Stability: Strong as of this session, and only as of it. The file carried nine `###` headings at the time of writing and no more. What changes it: another session appending a question to that file; nothing in this folder's own state would reveal it.
- **`modules/process/control-flow/protocol/` gains no declaration before the owner question is ruled** — Stability: Strong. `docs/protocols/process/control-flow.handoff.md:11` states it, and `modules/khayyam/targets/js/target.changelog.md:57` records that the model's settling preceded any code.
