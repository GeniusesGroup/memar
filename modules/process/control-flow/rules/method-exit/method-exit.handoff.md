# Control Flow Rule — Method Exit Handoff
Open state for [method-exit.md](./method-exit.md). See the repository's [documentation-handoff.md](../../../../../modules-plugable/knowledge/documentation/handoff/handoff.md) for what a handoff is.

## Status
Active — drafted 2026-10-03 on the owner's ruling that leaving a method early is a flow-control concept like any other, that it needs no new keyword because a transparent method can be introduced instead, and that a reader who uses it where it does not belong gets a linter error. Carried forward 2026-10-04, when the owner's ruling that `return` left the grammar graduated into the language document and this Rule's *What this rule does not claim* was corrected to match it.

## Placement
The Rule is in `modules/process/control-flow/rules/method-exit/` rather than in the Khayyam catalog, and the criterion is [Rule → Which Module a Rule Belongs To](../../../rule/rule.md#which-module-a-rule-belongs-to) read with the placement criterion the owner stated on 2026-10-03 — a rule belongs to a language exactly when no program satisfies every rule of that catalog and still violates it. Two questions follow, and they answer differently.

- **Is it the language's?** No, and the test settles it rather than judgement: a realization may spell the exit as a grammar command, as a library method, or as both, and a program that writes the operation this Rule points at means the same thing under each. Turning the condition off changes no program's meaning, only whether a reader is corrected — so the obligation belongs to the tool that applies it, per [Khayyam → Minimal Legislation](../../../../../docs/khayyam/khayyam.md#minimal-legislation-a-principle) at `:178`.
- **Which module owns it, then?** Flow control does, because the concern is a decision about where execution continues. [Control Flow → Library-Defined Control Flow](../../control-flow.md#library-defined-control-flow) states that a mid-scope return is an ordinary control-flow operation, and the [Control Flow model](../../docs/control-flow.md#flow-decision) records a return as a Flow Decision whose derived target is past the call. `docs/modules/README.md:16` names this module as the protocol's implementation module.

**The name follows the model's own vocabulary rather than the grammar's.** `Return` would name one spelling of the operation rather than the concern, and a Rule must not take the name of a construct whose existence it does not claim; `Method Exit` names the concern — an execution leaving the method whose body it runs — which holds whichever way a realization spells it, and it sits beside `halt-declaration` as the Rule for the other way an execution ends. `Method Return` was considered and refused for the same reason. Neither name is settled by this entry: the owner may prefer a third.

## Open Questions
- **Which type owns the exit operation, and what it is called.** [Control Flow → Which type owns the control-flow forms and what category is it](../../control-flow.handoff.md#which-type-owns-the-control-flow-forms-and-what-category-is-it) is open for the whole family of flow forms, and the model records at `modules/process/control-flow/control-flow.handoff.md` that the library's owner type, the type of a scope parameter, the type of a condition, and whether a form carries an error output are all unsettled. The Rule states no declaration and no spelling; `Return` on a type named for the module is one candidate the owner's ruling named as an example of a method that can be introduced, not as a decision.
- **What a tool compares where a realization spells the exit more than one way.** A tool reports a call to the exit operation in a position it does not serve, and the check is against the declaration the flow-control module publishes rather than against a word ([Control Flow Rule — Method Exit → The rule](./method-exit.md#the-rule)). Where a realization spells the exit twice — as a command and as a method — a tool has two spellings to recognize and must say whether a source may use both, one, or neither. In this repository the grammar carries neither spelling, so the question is carried for a realization rather than settled here.
- **Whether a scope's teardown runs on the way out.** The protocol registers halting semantics as a topic to be developed ([Control Flow → Topics to be developed here](../../control-flow.md#topics-to-be-developed-here) at `:147`), and [Compiler → The branch body a flow-control module receives](../../../../computer/compiler/compiler.md#the-branch-body-a-flow-control-module-receives) at `:73` leaves open what a body hands back to its driver. An exit that leaves a method while a scope's body is still suspended meets both questions; neither is answered here.
