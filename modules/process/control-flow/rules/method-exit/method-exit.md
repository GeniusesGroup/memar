# Control Flow Rule — Method Exit
Control Flow's rules live one rule per folder under [`modules/process/control-flow/rules/`](../README.md), and this is the Rule for an execution that leaves the method whose body it is running — before that body's last command, or from inside a scope within it. It is a governance rule of this repository, held for the [Control Flow protocol](../../control-flow.md), whose document owns the concern: [Control Flow → Library-Defined Control Flow](../../control-flow.md#library-defined-control-flow) states that a code scope names *what* would run while an explicit control-flow operation decides *when*, calls a mid-scope return an ordinary control flow operation, and keeps the scope and the transition as distinct concerns. The [Control Flow model](../../docs/control-flow.md#flow-decision) names the operation a **Flow Decision** and records its derived target — past the call, for a return. This Rule states what a reader does when they reach for leaving, and what the check is that tells them.

## The rule
- **Leaving a method early is an operation, and it is reached through the flow-control library.** A reader who wants an execution to stop before the end of the body writes the flow-control module's exit operation — the method its owner type declares for that purpose, called the way any other method in this language is called — and not a word of the grammar. Nothing here needs a new keyword: [Control Flow → Library-Defined Control Flow](../../control-flow.md#library-defined-control-flow) requires of a flow construct only that it be an explicit operation over the branch-grouping primitive, and [Control Flow → Structured and Unstructured Flow as Libraries](../../control-flow.md#structured-and-unstructured-flow-as-libraries) makes a jump-shaped form exactly as valid and exactly as unprivileged as a branch pair. An exit is one of that family, and a transparent method is how a library supplies it.
- **The operation is written where the reader of the call site can see it, and its misuse is reported.** A call to an exit operation in a position the operation does not serve is a finding, not a preference: a linter configured with this Rule reports it, per [Linter → Configuration and override](../../../../computer/linter/linter.md#configuration-and-override). What makes it checkable is that the operation is an ordinary method with an ordinary signature — the check compares the call site against the declaration the flow-control module publishes, and needs no knowledge of any keyword.
- **Which execution leaves is the signature's business, and this Rule does not settle it.** An exit's target is a derived target of the decision: past the call is what a return means, and [Control Flow → Library-Defined Control Flow](../../control-flow.md#library-defined-control-flow) is where an exit's having a derived target rather than a name or a value is stated, and why that is what makes it a decision. Nothing further has to be answered before a library declares the operation, and the declaration is where the answer is read: it is the flow-control module's to write.
- **Halting is not this Rule's subject.** Ending an execution outright, without passing through the ordinary path of any decision, is the [halt declaration Rule](../halt-declaration/halt-declaration.md)'s, in this same folder. A reader who means to end the run rather than to leave a method reads that Rule.

## Why it exists
The reason is the language's own, stated as a principle rather than as a list of missing keywords. [Khayyam → The Grammar Refuses Protocol Semantics](../../../../../docs/khayyam/khayyam.md#the-grammar-refuses-protocol-semantics) holds that a construct enters a grammar only when its semantics can be stated without adopting any protocol's definitions, and [Control Flow → Error Propagation](../../control-flow.md#error-propagation) at `:139` names that choice for flow specifically: this protocol's realization "offers no dedicated error syntax, a choice that belongs to that language's layer". What an exit *is* — leaving an execution whose body has not finished — is a control-flow fact stated by a control-flow protocol, and no protocol's definition needs to enter a grammar for a library method to perform it. The strength this architecture claims is therefore not that the word is missing but that **nothing is missing**: the operation is introduced as a transparent method, and a reader who misuses it is told so by a check rather than by a parser that had to grow a keyword to object.

That is also why the condition is this repository's and not the language's. [Khayyam → Minimal Legislation](../../../../../docs/khayyam/khayyam.md#minimal-legislation-a-principle) at `:178` puts a condition whose handling may differ between realizations in the tool that applies it, and whether a realization spells an exit as a command, as a method, or as both is a realization's choice — so what a reader does about reaching for the wrong one is a rule of a tool, which is what this is. The three claims behind that choice — a behavior is introducible as an ordinary method, a misuse of it is a tool's finding rather than a parser's, and a keyword is a reservation held for the language's lifetime — are recorded where the language document sends the reasons a flow construct was not added to a grammar, at Control Flow Changelog, entry *An exit is a decision, and the language needs no word for it*.

## Keep it or drop it
An organization may keep this Rule and configure its tooling to report the misuse, keep the Rule as the statement of where the operation lives while reporting nothing, or drop it. Dropping it costs the reader the one sentence that says which declaration to call, and leaves the operation discoverable only by reading the flow-control library's own declarations — which [Khayyam → Self-Documenting Code and Naming](../../../../../docs/khayyam/khayyam.md#self-documenting-code-and-naming) holds the language already makes possible, since a behavior is a method on the type that owns it. What no organization may do is change what an exit is while keeping the name.

## What this rule does not claim
- **It does not claim how a realization spells the operation.** The language this repository develops states in [Khayyam → Scope](../../../../../docs/khayyam/khayyam.md#scope) that the grammar ships no keyword for leaving a method early, and a source that writes one is refused as a form a body does not take; what leaves a method is a method some type declares, and until a library declares one a program written in this language has no way to leave a method early. Three statements of this Rule hold under that and under any other spelling: that the flow-control module's method is where a reader is pointed, that a call to it in a position it does not serve is reported, and that the report is a check against a declaration rather than a parser's knowledge of a word. What a spelling changes is only what a tool recognizes — a word, a name on a type, or both — and this Rule's requirement is satisfied by whichever the realization uses.
- **It does not claim which type owns the operation, or what it is called.** Control Flow → Which type owns the control-flow forms and what category is it is open, and the protocol's own examples write their calls without an owner. A name such as `Return` on a type named for the flow-control module is one candidate spelling among the owner's to choose; this Rule uses it only to name the operation, and states no declaration.
- **It does not design the operation's contract.** What an exit carries, what happens to a value the body was producing, and what happens to a scope's teardown on the way out are the protocol's and the library's, not this Rule's.
- **It does not claim the language requires any of it, and it does not claim a second toolchain must.** The same realization may spell the operation differently, drop the Rule, and keep the library; what it may not do is change what an exit means while reading the same source as this Rule reads it.
- **It does not claim anything about what any body of Khayyam source does.** No file, declaration, or emitted behavior in this repository is evidence for or against this Rule, and none is cited.
