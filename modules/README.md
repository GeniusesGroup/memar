# Modules (`modules/`)

## What this layer is
Implementation modules: the realizations of what the specifications state — protocol implementations and the Khayyam library sources (`.kh`). Every module here is reusable; what runs or aggregates modules — a server, an executable, a language's toolchain — is a bundle and lives under [`bundles/`](../bundles/README.md). A module here is the same responsibility [`docs/modules/`](../docs/modules/README.md) specifies, in the sense of [Modularity → Module as a System](../docs/modularity.md#module-as-a-system); the two trees are two representations of one module, its specification there and its realization here. The module index fixes the boundary: "Implementation modules live under `modules/` in this repository" ([docs/modules → Where implementations live](../docs/modules/README.md#where-implementations-live)), while the specification folder itself is "not executable code". Within this layer, placement follows the responsibility a folder names, the category layout is the one [docs/modules → One layout for both trees](../docs/modules/README.md#one-layout-for-both-trees) decides, and each module states its own membership criterion in its own README.

## Why a folder may exist before it holds code
A folder here is a carrier of thinking, not a container waiting for code. Much of this project's design reasoning lived in folder names long before it lived in documents; where the folders were absent, those ideas went unevaluated and the work fell into the ecosystem's general patterns by default — the outcome this project's own principles reject. A folder created ahead of its content keeps a decided direction visible and gives each idea a place to be argued about.

Three rules follow, and they are decisions rather than preferences:
- **An empty folder is a decision made visible.** Do not delete one for being empty; restructure it only with an argument.
- **No folder here is final.** Names may be merged, split, moved, or retired whenever the responsibility they name is better served another way.
- **A folder without a README carries its intent in its name** until one is written; a README is what makes the membership criterion inspectable.

## The kinds of folder here
- **By responsibility** — `computer/`, `process/`, `memory/`, `net/`, `codec/`, `string/`, `math/`, `time/`, `identifier/`, `hardware/`, `crypto/`, `gui/`, `lib/`, `runtime/`. Several of these carry a second level that is itself a set of ideas (for example `process/rule/` and `process/rules-engine/` — a rule, and the general mechanism that executes rules by their stated conditions).
- **A record that runs nothing** — the Go target's [research record](../bundles/khayyam/targets/go/target.research.001.md) holds the port's residue and where two archives disagree; it is a record, not a category.
- **By mechanism, language-independent** — `computer/lexer/` and the general rule engine are shared: they must not import a language's knowledge, and a language keeps only its own model beside its toolchain ([khayyam → Membership criterion](../bundles/khayyam/README.md)).
- **By role inside a module** — a module that carries more than one kind of work groups them, so that the module's root stays a list of kinds rather than a list of instances. The roles in use are `protocol/` (the module's one protocol surface), `rules/` ([Rule → Where Rules Live](../docs/rule.md#where-rules-live-rules-beside-protocol)), `errors/` (one folder or file per error), `tests/` (one Test per named Process, [Test → The rule](../modules/process/test/rules/test-placement/test-placement.md#the-rule)), `services/` (one folder per service the module offers), and `docs/` (documents about the module that are not its specification — notes, research, reports; the specification stays in [`docs/modules/`](../docs/modules/README.md#one-layout-for-both-trees), and a document a governing rule places beside its base artifact stays there). The list is not closed: a kind of work that recurs across modules becomes a role here once it is named. A role folder is named for the kind it holds rather than for the instance inside it: one service is `services/<name>/`, and a module with a single service still groups it, because the root is read as a list of kinds and an instance standing in a kind's place is what makes a root stop being one. A role folder carries the role's name exactly, with no prefix or suffix — not `test/` for `tests/`, not `services____/` for `services/` — because the name is how a reader and a tool find the role, and a padded name hides it from both; a folder a tool must not read is kept from it by that tool's own configuration, not by renaming. A folder that shares a role's name is not always that role: [`process/test/`](./process/test/) and [`process/error/`](./process/error/) are modules that develop the Test and Error concepts, each with role folders of its own, and a folder is read as a role only where it sits inside the module whose work it groups.

## The sources, and what they are not
This repository's Khayyam source files — the `.kh` tree under `modules/**`, and the port's files the Memar server still carries under [`bundles/memar/`](../bundles/memar/memar.md) — are called **the sources**. They were produced by porting an existing Go implementation into Khayyam ([the Go target's research record](../bundles/khayyam/targets/go/target.research.001.md) records that work and what it left behind), and they were never written in the language's final syntax. They are a record of that conversion, kept as record: the owner has ruled them neither evidence nor a premise, so no claim in this repository rests on what they happen to contain, and a measurement over them describes the sources rather than the language. The word the sources replaced — *corpus* — was left to its ordinary sense, which is a body of written text.

The name says what the files are and nothing more. What the sources are *for* is a separate question, and it is not answered here or anywhere by their name.

## What does not belong here
- **Specifications and general claims** — those live in the repository's [`docs/`](../docs/); this layer realizes them, it does not restate them.
- **What runs or aggregates modules** — servers, executables, and toolchains, the Khayyam toolchain and the Memar server among them, are bundles ([`bundles/`](../bundles/README.md)).
- **Generated output** — compiled artifacts and caches live in git-ignored `build/` folders.
- **A language-specific dependency inside a shared mechanism** — a language-agnostic implementation that acquires Khayyam knowledge stops being language-agnostic.
