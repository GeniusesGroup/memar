# Khayyam Python Target
## Abstract
This document is the Python target of the Khayyam toolchain, and today it holds one thing: the profile a Python source follows so that its later conversion to Khayyam is a translation and not a redesign. The owner ruled on 2026-10-24 that a Memar-built system is written in Python, following Memar's development framework and Memar's existing Python code, and that Khayyam replaces the Python when Khayyam is ready. A translation is mechanical only where every construct of the source has one Khayyam form. The profile therefore admits the Python constructs whose Khayyam form a Khayyam document states, refuses those that have none, and names the constructs whose form is still open: loops and jumps, unbounded integers and formatted text, and the import of a pluggable module ([What the profile does not yet cover](#what-the-profile-does-not-yet-cover)). Converting code that uses an admitted construct is mechanical; converting code that uses an open one is not, until its form is stated. Nothing here converts anything yet, and no Python artifact is emitted from Khayyam: the folder is named for the language, beside [`go/`](../go/target.md) and [`js/`](../js/target.md), as the Go target is. Every rule below is Tentative until the owner ratifies the profile ([handoff](./target.handoff.md)).

## Introduction
### Motivation
The Go port shows what a conversion leaves when only declarations are carried. Its bridge wrote abstractions, capsules, fields and method signatures, a Go declaration leaving the residue block when a Khayyam declaration matches it by name and arity, and it wrote no bodies: "A Go function with a body is never carried, because the port writes no bodies" ([`go-clue-residue` → The rule](../go/rules/go-clue-residue/go-clue-residue.md#the-rule)). The residue is therefore the work the bridge never attempted, every method body among it. `rg -l "TODO\(go-migrate\)" --glob "*.kh"`, run at the repository root on 2026-10-24, lists 1,814 files that still hold a residue block; [Go target → Motivation](../go/target.md#motivation) states 852, a figure that command no longer gives. The residue is not by itself proof that the forms in it cannot cross into Khayyam: no bridge from any source language has yet translated a body, so which body constructs translate is untested. What the port does show is the cost of a source whose bodies are left to be carried by hand afterwards, and a Python code base written for a Memar-built system over months would hand its conversion the same work unless each construct it uses has a stated Khayyam form from the first line. The profile is the cheapest place to state those forms and to keep out what has none: a rule a checker applies while code is written, rather than a redesign after it is.

### Methodology
Each rule names the Khayyam form it maps to and the document that states that form: the mechanical mapping of [Khayyam Practice → Translating from other languages](../../../../docs/khayyam/khayyam.practice.md#translating-from-other-languages-mechanical-mapping), the commands a body may hold ([JavaScript target → The commands a body may hold](../js/target.md#the-commands-a-body-may-hold)), and the language documents those cite. The evidence for what Memar's Python already looks like is its own code, for example [`claim.py`](../../../../modules/management/task/primitive/claim.py), a frozen data class whose constants are declared once on the type, and [`priority.py`](../../../../modules/management/task/services/priority.py), a service of plain functions. A rule that the existing code breaks says so. `claim.py` predates the profile and breaks it in four places: its field `folder` is public; it reads the filesystem and the clock, with `try` and `except OSError`, inside a primitive rather than a host binding; `stale_hours` is a `classmethod`, where the profile's example below writes it as a static method; and it computes with operators (`time.time() - touched < self.STALE_SECONDS`). The Scope's exclusion of present tooling is what keeps these from being refusals today.

## Explanation
### Scope of the profile
The profile binds Python that is to be carried into Khayyam: the protocols, primitives, services and rules of Memar's modules written for a Memar-built system, and the adopting organization's own modules. It does not bind Memar's present tooling, which was written before the profile; that code is carried into Khayyam only after it is brought under the profile, as [UI Handoff](../../../../modules/computer/ui/ui.handoff.md) already says of the command module's Python. It does not bind a host binding (below), which is not converted.

### Domain code and host bindings
A module's Python is in two kinds of file, and the two are never mixed in one file.
- **Domain code** is everything the module states: its abstractions, capsules, methods, rules and services. It imports only the standard library's typing and data-class forms, other domain code, and the abstractions of host bindings. It is what the conversion translates.
- **A host binding** is the code that reaches what the language does not state: the operating system, a socket, the HTTP server, the database driver, a cryptographic library, the clock. It realizes an abstraction the domain code declares and is reached only through it. In Khayyam it is a body-less method on a capsule, whose implementation the host supplies when the program is linked ([JavaScript target → The three kinds of body-less method](../js/target.md#the-three-kinds-of-body-less-method)), so it is rewritten for each host and never translated. A third-party package is imported only in a host binding.

The share of host bindings is what a conversion costs beyond translation, so a module keeps them small: one binding file per foreign capability, no domain decision inside it.

### The rules
Each rule is stated with the form it maps to. A construct not admitted here is refused by the checker rather than left to the converter to guess.

| Python | Khayyam form | Rule |
| --- | --- | --- |
| `class X(Protocol)` with method signatures and `...` bodies | `ab` | An abstraction holds signatures only: no state, no method body, no default. |
| `@dataclass(frozen=True, slots=True) class X` | `cp` | A capsule's fields are read only through its methods. A field is named with a leading underscore and never read from outside the class. |
| a method `def m(self, a: A) -> ...` | `mt` with `self` the capsule | Every function is a method of a parent type. A function that would be free is a `@staticmethod` of the capsule it belongs to, called on the type: `Claim.stale_hours()` maps to `Claim.StaleHours()()`. A module-level function is allowed only in a service file, where the file's service capsule is its parent. |
| `return total, err` | the influenced group `(total T, err Error)` | Every `return` of a method returns the same named locals in the same order; their names and annotations are the influenced group. |
| `total, err = W32.sum(a, b)` | `vr total W32`, `vr err Error`, `W32.Sum(a, b)(total, err)` | A statement holds one call whose results it binds. Nested calls are allowed; the converter flattens them left to right into declared variables, the order Python evaluates them in. |
| a fallible method | an explicit error output ([Control Flow → Error Propagation](../../../../modules/process/control-flow/control-flow.md#error-propagation)) | A domain error is returned, never raised. Each concrete error is its own type ([The Error](../../../../modules/process/error/error.md)). `raise`, `try` and `except` appear only in a host binding, which turns a foreign exception into a returned error at the seam. |
| a mutation of state | a method that performs it ([Khayyam Practice](../../../../docs/khayyam/khayyam.practice.md#translating-from-other-languages-mechanical-mapping): mutation is an explicit method call) | A capsule whose state changes is not frozen, and only its own mutator methods assign to its fields; a mutator's results are at most an error. The converter sorts a capsule's methods into observers and mutators by whether they assign to `self`, as the `.observers.kh` and `.mutators.kh` files of the modules are sorted. |
| a copy | an explicit `copy_from`-style method | No implicit copy: `copy.copy`, `copy.deepcopy` and slicing a capsule's sequence to copy it are refused. |
| a literal | a value of a named capsule ([Separation of Syntax and Governance](../../../../docs/khayyam/khayyam.md#separation-of-syntax-and-governance-a-principle): no bare literal without a named capsule) | A number or a string other than a human-language text is declared once, as a `ClassVar` on the capsule that owns it, as `Claim.STALE_SECONDS` is. Human-language text is a method of the type, in Persian and in English ([Software → No Hidden Inputs](../../../../modules/process/software/software.md#no-hidden-inputs)). |
| `str`, `int`, `bool` holding domain meaning | a named capsule ([Resistance to Primitive Obsession](../../../../docs/khayyam/khayyam.md#resistance-to-primitive-obsession)) | A value with business meaning is a capsule of its own, as `TaskId` and `Priority` are; a builtin type appears only inside a capsule's fields and in host bindings. |
| `a + b`, `a - b`, `a * b`, `a / b`, `a == b`, `a < b` | a method of the value's capsule with an explicit error output, `a.Add(b)(c, err)` ([Variable → Domain-Driven Arithmetic](../../../../docs/khayyam/variable.md#domain-driven-arithmetic)) | Domain code writes no operator: arithmetic and comparison are methods of the capsule that owns the value (`total, err = a.add(b)`), and a failure such as overflow or division by zero is that method's returned error, so `ZeroDivisionError` and `OverflowError` never reach domain code. The operators on a builtin number are written only inside the host binding that realizes the number capsule, as the arithmetic of `modules/math/` is a provision whose body the host supplies. Which capsule a Python `int` holding a quantity becomes is open (below). |
| `xs[i]`, `xs[a:b]`, `d[k]`, `len(xs)`, `k in d` on a value with domain meaning | a method of a domain-specific container capsule ([Polymorphism → Polymorphism Without Generics: Domain-Specific Containers](../../../../docs/khayyam/polymorphism.md#polymorphism-without-generics-domain-specific-containers)) over the raw ADT protocols, `Array_Dynamic` for an ordered run and `Array_Associative` for a map ([Abstract Data Types → Established translations](../../../../modules/computer/adt/adt.md#established-translations)), whose `Lookup` returns `(value, err)` | A collection with domain meaning is a capsule of its own (`PermitList`, not `list[Permit]`) whose methods take and return its element type. Indexing, slicing, lookup and length on a builtin `list` or `dict` are written only inside the host binding that realizes the raw ADT protocol, which turns `IndexError` and `KeyError` into the returned error at the seam, so domain code never catches them. |
| absence | a type's own contract ([Memory → Absence is a type's contract](../../../../modules/computer/memory/memory.md#absence-is-a-types-contract-not-a-universal-machine-condition)) | `None` is the "no error" value of an error output and nothing else. A value that may be absent is a result the type states, as the record port's Found, Absent and Unavailable are. |
| `if`, `elif`, `else` | the flow library's conditional over a scope ([Control Flow](../../../../modules/process/control-flow/control-flow.md)), declared in draft as `IF` in `modules/process/control-flow/protocol/if.kh` | A condition is one name or one call; a comparison or a boolean operator on two values is written as a method of their capsule (`a.is_before(b)`), since the grammar ships no operator. |
| `for`, `while`, `break`, `continue`, an early `return` | open: the loop and jump files of `modules/process/control-flow/protocol/` (`for.kh`, `while.kh`, `loop.kh`, `break.kh`, `continue.kh`) declare nothing yet | Admitted and marked by the checker, under one label per form, so that each use can be found when the flow library declares its form; `break`, `continue` and an early `return` only as the last command of a branch. Until then a body that holds one is not mechanically convertible (below). |
| `import` | `tp X in "path"` ([Khayyam → Import Mechanism](../../../../docs/khayyam/khayyam.md#import-mechanism-in)) | `from a.b.c import X`, one name per line, the path being the repository path. No `as`, since Khayyam has no renaming include, and no `*`. A module under `modules-plugable/` cannot be named this way, since that folder's name is not a Python identifier; how it is imported is open (below). |
| a name: `stale_hours`, `task_id` | the Khayyam name the [identifier-naming rule](../../rules/identifier-naming/identifier-naming.md) gives, qualified by the [qualified-names rule](../../rules/qualified-names/qualified-names.md) where it collides (`Timer_Start`) | A method, field or type is named in Python by Python's convention and converted to the PascalCase form; the converter applies the qualified-names rule and reports a collision it finds, never renames silently. |
| `@dataclass`, `@staticmethod`, `@classmethod`, `@property` | structure the converter reads | The only decorators admitted, because each states structure and wraps no behaviour. A decorator that wraps behaviour (caching, retry, logging, a route) is refused ([Metaprogramming](../../../../docs/khayyam/metaprogramming.md)): the behaviour is written as visible composition. |
| `async def`, `await`, threads in domain code | refused in domain code, though Khayyam has a form: [Khayyam Practice](../../../../docs/khayyam/khayyam.practice.md#translating-from-other-languages-mechanical-mapping) maps `async` and `await` to tagging the method at its definition, and [Runtime](../../../../modules/computer/runtime/runtime.md) makes concurrency a hosted library | Domain code is synchronous. The profile is stricter than the mapping because nothing in domain code needs concurrency: the serving process runs calls on its own workers, so concurrency is the host's. |
| `TypeVar`, `Generic`, `lambda`, a nested `def`, a generator, `yield`, a comprehension | none | Refused. A generic is rewritten around an abstraction ([Khayyam Practice](../../../../docs/khayyam/khayyam.practice.md#translating-from-other-languages-mechanical-mapping)); a closure or a lambda becomes a method of a capsule holding what it captured; a comprehension is a loop. |
| inheritance of an implementation, a mixin, a metaclass, `__getattr__`, `eval`, `exec`, monkey-patching, `**kwargs` | none | Refused. A class names only the abstractions it realizes. |
| annotations | the declared types of every group | Every parameter, result and field is annotated, `Any` is refused, and a type checker runs in strict mode over domain code, so the converter knows each receiver's type. |

### What the profile does not yet cover
A construct is covered when a Khayyam document states its form. Four are not, and each is a working answer, Tentative, in the [handoff](./target.handoff.md#decisions) rather than a form chosen here:
- **Loops and jumps.** The conditional is declared in draft; the loop and jump files of the flow library declare nothing, so a translation of `for`, `while`, `break`, `continue` or an early `return` would be a design of those forms, not a mapping.
- **Unbounded integers and formatted text.** A Python `int` has no bound, and the number tower names only widths ([Math → The number tower](../../../../modules/math/math.md#the-number-tower)), so which capsule a Python integer becomes, and what its overflow is, is not stated; nor is the form of text built from values, as an f-string or `format` builds it.
- **The import of a pluggable module.** Khayyam's `tp X in "modules-plugable/..."` names one, but Python cannot spell that path in an `import`.

Converting code that uses none of these is mechanical by the table. Converting code that uses one is not, until its form is stated, and the hand conversion this target owes (below) is the test of whether the table is enough; it has not been run.

### How a conversion is accepted
A conversion is accepted when the module's contract suite, the given-when-then tests written against its protocol, passes on the Khayyam realization as it passed on the Python one. The record port's suite is the model: it is written against the contract and runs against every adapter ([Memory Record → The contract suite](../../../../modules-plugable/computer/memory/store/record/record.md#the-contract-suite)). So every module written under this profile carries tests against its protocol, not against its Python internals, and those tests are what proves the translation.

### What this target owes
- A checker that reads a Python source and refuses every construct the table does not admit, under one label per refusal, run before a commit on domain code.
- The bridge that writes Khayyam from a profiled source, owed when the Khayyam toolchain can compile the result; until then a hand conversion of one module checks that the profile is enough.
