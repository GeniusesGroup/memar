# Rename Management
What the declaration-rename mechanism is made of, layer by layer, for this repository's Khayyam toolchain. The rule it realizes is [`declaration-rename`](../../rules/declaration-rename/declaration-rename.md); what this document adds is the classification the rule's own handoff could not settle, stated with the instrument the repository already owns rather than with a new one.

## The instrument, and the limit it has
[`modules/process/control-flow/flow-management.md:243`](../../../../modules/process/control-flow/flow-management.md) states the test this document applies: **language-level** is what a document states about what a program may mean, decided by the coincidence test — *were a second target to state the same thing the same way, that would not make it language-level, it would make it a coincidence between two tools*; **per-target** is what each realization states for itself and would state differently; **protocol-level** is a claim whose home is a document under [`docs/modules/`](../../../../docs/modules/), which the language cannot discharge at all.

That instrument separates **a language from its own targets**. It does not separate **one language from another**, and the difference is not a nicety. The coincidence test asks whether a *second target* would state the same thing identically; a second *language* is not a target, and nothing in this repository decides what a second language would state. So the table below can say with precision which of the rename's claims are Khayyam's and which are this port's, and it **cannot** say that any of them would hold for a language this repository does not have. That limit is the finding, not a gap in the table.

## The classification
| Claim | Level | Why |
| --- | --- | --- |
| An identifier is a whole token, so a comment and a string literal are not places a name is bound | **Language-level** | Stated by the language and naming no target ([Khayyam → Keywords](../../../../docs/khayyam/khayyam.md)). A second target scans differently and decides the same thing. |
| Which names a declaration references | **Language-level** | Stated once, in this repository's own representation: `referencedTypes` ([`core/src/sr.ts:135`](../../core/src/sr.ts)). No target states it, and the editor derives its answer from it ([`lsp/src/unbound-names.ts:94`](../../lsp/src/unbound-names.ts)). |
| Where each referenced name stands in the text | **Language-level** | Stated once, by the language's own frontend: [`core/src/references.ts`](../../core/src/references.ts). It was stated **twice** until 2026-10-05 — there and at the binding — and the duplication is what this row now exists to keep single. |
| Which names a unit can see, and which file each arrived from | **Language-level** | Held privately by [`core/src/frontend.ts:34`](../../core/src/frontend.ts) and re-derived by hand at [`khayyam-binding.ts:373`](./khayyam-binding.ts). The claim is the resolver's; the mirror is the duplication. |
| Whether a unit's text still means something | **Language-level** | [`core/src/frontend.ts:80`](../../core/src/frontend.ts), asked per file with the rest of the corpus readable. Every compiler this repository holds answers it; no target states it. |
| Two owners of one name is an architecture error rather than a disambiguation problem | **Language-level**, and contested as a catalog membership | The language calls it that ([Import Mechanism (`in`)](../../../../docs/khayyam/khayyam.md)). Whether the *rule* belongs to this catalog is the disagreement [`rules/README.md:74`](../../rules/README.md) already records: the belonging test's two halves give opposite answers on it. |
| The corpus is the `.kh` units under given prefixes, and what a unit is called is the caller's fact | **Per-target** | This repository's arrangement, supplied by [`rename.ts`](./rename.ts) and by nothing in the language. |
| A Go clue block's extent, and that a block sealed by its sha256 is left whole | **Per-target** | A fact about the Go port's rule and this repository's block format. A target with no Go port states neither, which is the coincidence test answering *per-target*. |
| `Binding`'s `second`, `foreignRegions`, `residue` and `proseClass` | **Per-target** | They exist because this repository's sources carry one port's residue. A second target answers none of these four, because it has no foreign reader — so under the test they are this target's facts, and a shared interface that carries them is carrying one target's arrangement. |
| The plan, the report, the write, the gate and the exit codes | **Neither** | No protocol owns a rename, and none is named. Following [`binding.md:162`](../../../../modules/computer/binding/binding.md), the honest reading is that these are this rule's own condition rather than a language's or a protocol's — carried here rather than claimed upward. |

## What the table settles
**The language side of this mechanism is four queries and a range.** Which names a declaration references; where each stands; which names a unit can see and where each came from; whether the text still means something. Every one of them is already answered by `core/`, and every one of them is a fact about Khayyam rather than about this port. What is missing is not an abstraction but a **publication**: `analyzeImports` is not exported, the one place that places a referenced name covers three declaration forms and deliberately stops short of the `vr` and `in` forms this rule needs ([`unbound-names.ts:28`](../../lsp/src/unbound-names.ts)), and so a caller with a different question has to walk the tokens itself. That is why this folder holds a second copy of a walk the editor already has, and it is also why a `Binding` interface arose: an interface is what you build when the answers are not published and each caller has to ask for them itself.

**So the answer to whether one mechanism could serve every language is yes in shape and unanswerable in this repository as it stands.** The engine — enumerate a corpus, turn ranges into a plan a reader can accept, apply it under an explicit request, refuse a write that would newly break a file, report everything found and left — holds for any language that declares names and binds them across files, because none of those steps asks what a token is. What does not hold across languages is the *vocabulary of roles*, and that is the correct place for it to differ. The boundary that would make this real is one query answered per language rather than seven members supplied per language; the seven-member shape exists because the four per-target members above had nowhere else to live.

## What this document does not claim
- **It does not claim a second language would behave this way.** The instrument has no second language to test against, and a second language is not a second target.
- **It does not claim the mechanism should move out of this module.** Its subject is Khayyam's naming, and [Rule → Which Module a Rule Belongs To](../../../../docs/rule.md#which-module-a-rule-belongs-to) puts a Rule where its subject is owned. What this document claims is narrower: the *engine* inside it is not Khayyam's, and the day a protocol owns it is the day it has somewhere else to go.
- **It does not claim the residue mode is wrong.** It claims the mode is this target's fact, and that a shared interface is the wrong place to keep a target's fact.
- **It does not propose a protocol document.** That the language-independent claim has no owner is recorded as an open question in the paired [handoff](./rename-management.handoff.md), because a protocol is introduced by its owner and not by a session that noticed the hole.
