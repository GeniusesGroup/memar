## Decided
### The placement, the label, and the module's end
- **Placement (owner, 2026-10-19):** the module is pluggable and its home is this folder; its Python realization moved here from `modules/process/command/` in the same change, which removed the one module name that stood in two placements in the same category.
- **The label stays `guest`.** The owner ruled on 2026-10-19 that the Command protocol is not Memar's, that Memar does not accept it, and that it will certainly be deleted. The module is a guest known to be temporary; the one thing built on it is the card `session start` prints, kept by the ruling below.
- **Its card stays in `session start`, though the edge runs backwards.** That service prints the card this module generates, so a kernel module names a pluggable one — the direction the placement rule refuses. The owner kept it on 2026-10-19: a second round trip for `memar commands` costs more than the edge, and this module and its need are temporary. The edge goes when the module does.

## Open Questions

### What protocol a command's help follows once `process/command/` is complete
- State: the command module (the owner's own and unfinished) already models a command as a Type: `protocol/command.kh` composes `Command_Handler` (`ServeCLA`), `Type`, `Observer_MediaType`, `Process_Request` and `Process_Response`, with `ParentCommand` and `SubCommand(name)` for the tree and `RunnableCommand` false for "a documentation pseudo-command". Its words come from the type's own methods, per human language in a locale file (`errors/*.locale.eng.kh`): `Quiddity` gives `Name`, `Abbreviation`, `Aliases`, and `Details` (`modules/computer/type/protocol/detail.kh`) gives `Summary`, "the '<app> help' output", and `Overview`, "the '<app> help <this-command>' output". `cla.kh` derives a command's flags from its capsule's fields (`FromCLA`, `ToCLA`); `serve.kh` leaves the generated help unwritten; `command.kh` notes "subcommands are in general best avoided" and asks whether `Command` should be deprecated in favour of a service. Memar's `.agents/scripts/` meanwhile builds its help with argparse inside each service's `describe(verbs)`: summary and overview are Python strings, flags are declared one by one, and the owner ruled (2026-10-14) that each help states only its own work, which is now kept by `.agents/scripts/tests/memar.py` (`HelpStatesItsOwnWork`) and stated in `.agents/scripts/memar`'s docstring. The scripts will become Khayyam ([Scripts → Maintaining this folder](../../../.agents/scripts/README.md#maintaining-this-folder)); which protocol their help then follows decides how much of today's help text survives that conversion.
- Options:
  1. **(recommended)** A command's help is generated from its Type: the one-line `Summary` in its parent's list, its own `Overview` under its own usage, the flags from its request type's fields, the words from its locale files, and nothing typed in a service. A domain that only groups is a non-runnable command whose `Overview` states what the domain is; one that also runs (as `memar session` moves left folders before every verb) needs `RunnableCommand` to say so. Cost: the generated help in `serve.kh` and a field-to-flag help in `cla.kh` must be designed first, and each script's help is rewritten into detail methods when it is converted.
  2. Keep sub-verbs only where a domain shares state, and make every capability a service addressed by its own name, per the note in `command.kh`. Cost: `memar <domain> <verb>` changes shape for every caller and document.
  3. Keep argparse's shape and carry it into Khayyam unchanged. Cost: help text stays typed in each service, the drift the ruling exists to stop.
- Also asked: where a recipe that crosses verbs belongs once help is generated — the queued-work recipe now in `memar session claims --help`, the hand-over in `memar session new --help` — a command's `Overview`, its `UserActionNote`, or the practice that already argues it ([Handoff Practice → Queued Work and Its Hand-Back](../../../modules/knowledge/documentation/handoff/handoff.practice.md#queued-work-and-its-hand-back)) with the help naming it.
- Anchor: `modules-plugable/process/command/protocol/command.kh`; the answer lands in a position document beside this module and in the router's docstring, `.agents/scripts/memar`.
- Blocks: nothing now; the module is not built on until it is complete. Meanwhile the scripts keep argparse, each help stating only its own work, by the owner's ruling of 2026-10-14.
- Asked: 2026-10-14, by Claude (session `20261014-T175052Z-9344`), on the owner's request.
- Superseded: the owner ruled on 2026-10-19 (see Decided) that the Command protocol is not Memar's and will be deleted, so no help protocol is designed for this module; the scripts keep argparse until the conversion.
