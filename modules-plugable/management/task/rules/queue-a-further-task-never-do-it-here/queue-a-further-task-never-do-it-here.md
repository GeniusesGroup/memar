# Task Rule — A Further Task Is Queued, Never Done in the Conversation
A rule of this repository for a conversation that turns up work beyond its own task. Moved on 2026-11-01 from the Handoff Practice.

## The rule
- **Every task a conversation carries spends its context, so a further task is recorded and not done there.** The conversation opens it as a queued task, writes its plan whole (the Request, the check that says it is done, the shape of its report, and its Why) and leaves it. It may queue any number, and never does a queued task's work in its own context.
- **Status Queued means planned and taken by no one;** it becomes Active when an agent claims it. A queued plan whose Request is empty is not ready, and is not taken.
- **Follow-up work found by a task is recorded the same way,** with the finding task named as the parent. It is work when its plan can state a change to be applied or a decision to be recorded as the check; a finding that must first be studied is that work's first step ([a task is for work](../a-task-is-for-work/a-task-is-for-work.md)).
- **What is not worth doing is not recorded.** What is worth doing but not yet decidable is recorded with the decision it waits for, as a [question of the task](../a-question-belongs-to-a-task/a-question-belongs-to-a-task.md).

## Why it exists
A conversation that did the work of each task it met would grow until every later turn paid for all of it, and a task not written whole cannot be taken by an agent that was not there.

## Keep it or drop it
An organization may work every task where it is found, and then pays one context for all of them.

## What this rule does not claim
- It does not give the verbs, options or limits; `memar task ensure --help` and the `--help` of each verb it names say them.
- It does not say who takes queued work: [queued work is taken for one project and one topic](../one-topic-one-project-per-delegated-batch/one-topic-one-project-per-delegated-batch.md).
- This repository runs no check of it today.
