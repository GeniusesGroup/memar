# Registry inquiry
A claim of its own, like any other claim. He compares it to theft. It asks a target organization for information. It is not a draft-gate that other cases must pass.

## Model
- The inquiry is a [case](../../../../../modules/rights/case/case.md). It has its own plaintiff, its own defendant, its own votes, and its own ruling.
- The defendant is the target organization. One defendant. Example: an account opened in someone else's name; the information must come from that organization into the forum.
- When the claim is accepted, the inquiry returns an information package. The requester can file a claim against that package. The requester does not receive the underlying records. Inquiry data stays off the person.
- The package is not a second defendant and not an edge drawn here. Its record is a content concern. This file does not model the content domain.

## Policies (rules)
- The claimant must prove the need. If that proof needs other claims, those claims are chained on [petition next](../../../../../modules/rights/case/edges/petition-next/petition-next.md), so the judge can see the inquiry is not a pretext to harvest information.
- Other cases do not wait on this claim. A filer may not know the defendant yet, so the draft chain may be absent, and the chain may change after the inquiry.
- The inquiry is optional in the same way as other kinds. An organization that does not inquire leaves it out.
- Two organizations are not two defendants on this case. A second organization is a second claim. Joint adjudication, as a direction, is that chain. Memar UUIDs name the organizations. A blockchain is not required for that identity. The joint procedure is not drawn here.
- Confidentiality here is the package rule above. It is not only a rule about judges.
- Reject on this case is a ruling of this case. It does not write a vote on another case.
- A reject shortcut on the inquiry is a ruling of that inquiry only. It does not write `vote_reject` on a later case, does not delete that case, and does not retarget `acceptance_required`. Model v2 closes its own critique failure with this rule and records it as a proposal implied by model v1 that awaits Omid; the repository has not ratified it.
- What would falsify that the inquiry is a claim like any other: an inquiry that is not a claim; a claimant who need not prove the need; or inquiry data written onto the person. Model v4 point 15.
- Until every required judge has voted, no party sees any judge's or expert's vote or explanatory text on this case.

## Placement
- **Here, with the other optional kinds,** as its own claim. The case node stays in the case domain.
- **Nearest alternative rejected:** a gate that holds later cases in draft until this inquiry is accepted.
- **Nearest alternative rejected:** a kernel node type "inquiry," distinct from case. A claim is a case.
- **Nearest alternative rejected:** delivering the underlying records to the requester.
- What would make a gate necessary: a merits case that cannot be filed until this inquiry exists and is accepted. That requirement is not recorded.

## Open questions
- None for a second defendant. The package's content shape is a note for the content domain, not an end of this claim.
