# Graph
In discrete mathematics, particularly in graph theory, a [graph](https://en.wikipedia.org/wiki/Graph_(discrete_mathematics)) is a structure consisting of a set of objects where some pairs of the objects are in some sense "related". The objects are represented by abstractions called vertices (also called nodes or points) and each of the related pairs of vertices is called an edge (also called link or line). Typically, a graph is depicted in diagrammatic form as a set of dots or circles for the vertices, joined by lines or curves for the edges.

Graphs are the basic subject studied by graph theory. The word "graph" was first used in this sense by J. J. Sylvester in 1878 due to a direct relation between mathematics and chemical structure (what he called a chemico-graphical image).

## Edge types
- The edges may be directed or undirected. For example, if the vertices represent people at a party, and there is an edge between two people if they shake hands, then this graph is undirected because any person A can shake hands with a person B only if B also shakes hands with A. In contrast, if an edge from a person A to a person B means that A owes money to B, then this graph is directed, because owing money is not necessarily reciprocated.
- [Loop](https://en.wikipedia.org/wiki/Loop_(graph_theory)) are edges that join a vertex to itself.
- Shortcut (or derived) edge is just short traversal for two or more edges. ## Relationship-distance queries: traversal vs precomputed edges
The recurring design question behind shortcut edges: answering "how is user A related to user B?" (LinkedIn-style friend-of-friend, friend-of-friend-of-friend) without traversing the social graph on every read. The resolved direction from the modeling discussion (2025-01-16):

- **Traversal (BFS/DFS) is always needed** to discover relations dynamically, but it is too expensive to run per read when the read is a user opening another user's page.
- **O(1) read time requires compute-and-store**: the distance/relation is precomputed and stored as a derived edge, paid for at write time (each new or removed relation invalidates and recomputes affected derived edges). There is no free lunch — the trade-off is write-time cost vs read-time cost, and for social-profile reads O(1) read wins.
- **Derived edges are caches, not truth**: a shortcut/derived edge (e.g. `connection_2nd`) must always be re-derivable from the authoritative base edges (`friendship`), must never become the source of truth, and is owned by the capability module that gives it meaning (shortcut edges are not separate modules; analytics that materialize derived knowledge is always pluggable).
- Degree labels are automatic (users cannot assign them); they are maintained by the system when the base relations change.

Algorithm inventory for the engine side (reference for implementers; the modeling decision above is independent of the choice): BFS (shortest path / degree discovery), DFS (reachability), incremental distance-update algorithms and dynamic all-pairs methods (Floyd-Warshall, Johnson) for write-time maintenance, distance matrices or key-value pair stores for precomputation (O(n^2) vs sparse), graph partitioning/clustering (Louvain, Girvan-Newman) for very large graphs, distance trees and metric-based indexing, and approximation approaches (sampling, ML-based link prediction) where exactness is not required.

## Graph theory
In mathematics and computer science, [graph theory](https://en.wikipedia.org/wiki/Graph_theory) is the study of graphs, which are mathematical structures used to model pairwise relations between objects. A graph in this context is made up of vertices (also called nodes or points) which are connected by edges (also called arcs, links, or lines). A distinction is made between undirected graphs, where edges link two vertices symmetrically, and directed graphs, where edges link two vertices asymmetrically. Graphs are one of the principal objects of study in discrete mathematics.

## Graph drawing
[Graph drawing](http://en.wikipedia.org/wiki/Graph_drawing) is an area of mathematics and computer science combining methods from geometric graph theory and information visualization to derive two-dimensional (or, sometimes, three-dimensional) depictions of graphs arising from applications such as social network analysis, cartography, linguistics, and bioinformatics.

A drawing of a graph or network diagram is a pictorial representation of the vertices and edges of a graph. This drawing should not be confused with the graph itself: very different layouts can correspond to the same graph. In the abstract, all that matters is which pairs of vertices are connected by edges. In the concrete, however, the arrangement of these vertices and edges within a drawing affects its understandability, usability, fabrication cost, and aesthetics. The problem gets worse if the graph changes over time by adding and deleting edges (dynamic graph drawing) and the goal is to preserve the user's mental map.

## What it is to the memory contract
Storing a graph adds no address kind, no operation and no guarantee to the memory contract ([Memory Store → The contract](../../../../../modules/computer/memory/store/store.md#the-contract)): an edge is a value under an address, the reverse side of an edge is written in the same atomic batch, and a derived edge is a cache rebuilt from `changes`. The module is held as it stands, and whether graph-shaped data needs a capsule of its own, as a layout over [Key-Value](../key_value/key_value.md), is open in [Graph Handoff](graph.handoff.md).
