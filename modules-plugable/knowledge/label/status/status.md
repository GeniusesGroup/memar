# Status
Status names where a document, or a piece of work, stands in its life. It is not a domain of its own: each value is a [label](../../../../modules/knowledge/label/label.md) that takes the meta-label `Status` (`Label_Status` under [label/labels](../../../../modules/knowledge/label/labels/Status.py)). General Status-kind words (Draft, Proposed, Final, …) are declared under [thing/labels](../../../../modules/identity/thing/labels/); domain-specific ones stay in that domain's `labels/`. Attachment is Label's edge `(record)-[:label]->(Draft)` — including **content**; every documentation template is content and may carry labels.

There is **no** front-matter or template key named `Status` / `status`. On Markdown content, Status-kind words (and any other labels on that content) are written under the key `Labels`, comma-separated — e.g. `Labels: Draft` or `Labels: Draft, guest`. That line is the **written form of the content record's label edges**, not a second store beside them: until edges live only on the content record, front-matter fields that are edges (Labels among them) *are* those edges as written. A stray `Status:` line is legacy; rewrite it to `Labels:` with the same word(s).

- Exactly one Status-kind word applies at a time among the labels a kind may use; other non-Status labels may sit beside it under the same `Labels` key. A kind never invents a Status word of its own; a word it needs is declared as `Label_<Word>` with `labels=(Label_Status,)`.
- A Status-kind label reports the item's own lifecycle, never informal or practical usage of what it holds.
- Where it attaches: through [Label edge](../../../../modules/knowledge/label/edges/label/label.md). For a task, the lifecycle Status-kind label is on the **task** node; plan and report contents do not repeat it as a Status key ([Plan](../../documentation/plan/facet.md), [Report](../../documentation/report/facet.md)). Plan's own `Labels` field holds linking labels (Topic, an act word such as design, …) — the same Labels concept, written for that content.
- How a task run ended is narrated in the report's Result part beside the task's Status-kind label. A dependency is Complete when the cited task carries `Complete`; only Complete is safe to depend on.
- An error or an exhausted budget is never reported `Complete` ([Acceptance Criteria](../../../../modules/management/agency/agency.md#acceptance-criteria)).
- The vocabulary is code once ([A Fact in Code Is Written Once](../../documentation/documentation.md#a-fact-in-code-is-written-once)): each word is a `Label_<Word>` type; `Label_Status` catalogs Status-kind members. This section lists none of the values.
