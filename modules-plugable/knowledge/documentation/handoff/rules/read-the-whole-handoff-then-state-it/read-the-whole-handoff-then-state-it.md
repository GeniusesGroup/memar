# Handoff Rule — Read the Whole Handoff, Then State It
A rule of this repository, held for [Handoff](../../handoff.md), which owns the claim in [Reader relationship](../../handoff.md#reader-relationship). This rule states how a task that continues from a handoff begins.

## The rule
- **It reads the contents of the timeline completely before responding.** The contents depend on one another: an assumption may qualify a decision, and an open question may block a next step.
- **It states the decisions it builds on and their confidence before advancing,** so a misreading surfaces at the start and not midway.
- **It moves the state by new contents.** A new decision is a new content with its confidence; an answer to a question refers to it; a changed direction is a decision that refers to the earlier. No content is edited ([No Record Is Written Beside a Document](../../../rules/no-record-beside-a-document/no-record-beside-a-document.md)).

## Why it exists
A partial reading defeats the contents, and a stale state is worse than an absent one because it is trusted.

## Keep it or drop it
An organization may let the receiving task read a summary. It then builds on the part of the state the summary kept.

## What this rule does not claim
- It does not say how the contents are found; the store does.
